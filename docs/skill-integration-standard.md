# AI 智能体完整 Skill 接入标准

本标准适用于本项目后续所有 Skill。目标是让网页 AI 智能体获得与 Codex 等价的 Skill 执行能力，而不是只读取一段说明文字。

## 一、定义

一个完整 Skill 包至少由以下部分构成：

- `SKILL.md`：业务目标、适用条件、工作流和判断规则。
- `agents/`：界面信息、默认任务和调用策略。
- `references/`：口径、业务规则、示例和验收规则。
- `assets/`：模板、图片、样例、映射文件等只读资产。
- `scripts/`：可复用的确定性执行程序；如不存在则不强制创建。
- 依赖声明：所需模型、MCP、文件格式、运行库和外部数据能力。
- 产物契约：必须生成什么文件、满足哪些结构和质量条件。

只把 `SKILL.md` 拼接进系统提示词，不属于 Skill 接入。

## 二、强制接入流程

### 1. Registry 注册与包校验

- Registry 必须发现整个包，而不是单个 Markdown 文件。
- 校验 frontmatter、清单引用、模板和必需资源是否存在。
- 为整个包计算版本哈希；任务运行期间禁止悄悄切换包版本。
- 二进制资产只返回元数据，智能体按需检查或复制，不把文件内容全部塞入上下文。

### 2. 能力与依赖挂载

- 文件能力：列出、读取、写入和登记运行文件。
- 包内脚本能力：只能执行当前包 `scripts/` 下的受信脚本，工作目录固定在本次任务空间。
- 数据能力：按 Skill 需求挂载真实数据源、检索或业务 MCP。
- 预测能力：提供可解释的方法、历史窗口、假设和结果，不允许用占位数字模拟。
- Office 能力：读取和更新原生可编辑图表、表格和文本，不以截图冒充可编辑交付物。
- 依赖缺失必须在执行前或工具调用时明确失败，不允许模型声称已经执行。

### 3. 隔离且可恢复的任务运行

每次执行必须创建唯一 `run_id`，并保存：

- `inputs/`：本轮输入。
- `working/`：中间文件、数据快照和渲染结果。
- `outputs/`：正式产物。
- `run-state.json`：任务图、状态、证据、产物和验收结果。
- `checkpoints.jsonl`：可恢复检查点。

原始 Skill 资产必须只读，所有修改都在运行工作区副本上完成。

### 4. 自主任务图与 ReAct 循环

智能体必须先根据 Skill 和用户目标建立任务图，每个任务节点至少包含：

- 任务 ID 与目标。
- 前置依赖。
- 成功标准。
- 当前状态。
- 工具证据和产物路径。

执行方式为“计划—行动—观察—更新—反思—继续”，而不是一次性生成长文本。工具结果、文件和验收报告是事实来源；模型文字不是完成证据。

### 5. 独立验收与自动修复

- 任务完成前必须由独立验收器检查任务图和要求的真实产物。
- PowerPoint 至少检查 ZIP 完整性、可重新读取、页数、原生图表/表格、外部文件依赖；环境支持时增加 Microsoft PowerPoint 实机打开与逐页渲染。
- 验收失败后，将结构化失败项反馈给智能体，进入有限次数的修复循环。
- 只有验收状态为 `passed` 时，才能发布下载地址并标记项目完成。

### 6. 保存、回放与审计

- 项目列表保存 `run_id`、任务图、工具调用、检查点、产物和验收结果。
- “查看任务”回放当时的运行状态，不重新生成一份摘要冒充原任务。
- Skill 包升级后，历史任务仍保留当时的包哈希和运行证据。

## 三、接入验收清单

每个新 Skill 必须全部满足：

- [ ] Registry 能发现并校验完整包。
- [ ] 智能体能读取 references 和检查 assets。
- [ ] 包内脚本可在隔离工作区执行。
- [ ] 所需数据、文件、预测和 Office 能力已真实挂载。
- [ ] 首次执行创建了持久化任务图和检查点。
- [ ] 服务重启后可根据 `run_id` 恢复。
- [ ] 代表性真实任务生成了要求的实际产物。
- [ ] 独立验收能够主动发现故意制造的错误。
- [ ] 验收失败能触发修复，修复后重新验收。
- [ ] 项目页能回放任务并下载已验收产物。
- [ ] Codex 与网页智能体对该 Skill 的资产和工具能力不存在实质差异。
- [ ] 测试覆盖正常、缺资源、工具失败、重启恢复和验收失败场景。

任何一项未满足，都只能标记为“接入中”，不能标记为“已接入”。

## 四、宏观经济月报的业务规则

- 输入目标月份即可执行，不要求业务人员先上传台账。
- 逐页数据台账是智能体运行中的内部工作产物。
- 当前或未来月份按预测任务处理；未来实际值尚未发布不是完整性错误。
- 必须区分实际期与预测期，并记录来源、信息截止日、预测方法和假设。
- 不得把上月值、零值或无依据数字写成目标月份实际值或预测值。

## 五、模型凭证边界

- 模型选择和凭证类型必须在任务开始前完成产品范围校验。
- 智谱 Coding Plan Key 不能用于网页智能体直接调用 BigModel 开放平台 API。
- 当前网页智能体中的智谱提供方保持禁用；只有配置兼容的开放平台 API Key 并通过真实预检后才能重新启用。
- 鉴权或产品范围错误不能解释为模型能力、输出质量或余额问题。
- 百炼业务空间/按量付费 Key 可在匹配地域和 Workspace Base URL 上供网页后端调用，但必须先通过 `/models` 和最小 `chat/completions` 双重预检。
- 百炼 Token Plan 专属 Key 的常规产品范围需要单独核验。用户已明确授权本项目本地网页服务使用 `qwen3.7-plus` 做一次真实 Skill 验证；验证结果必须以实际任务和产物验收为准，不能据此推断生产部署范围。
