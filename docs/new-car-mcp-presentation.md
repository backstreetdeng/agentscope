# 新车展示同源改造（2026-10-12）

## 唯一读取链路

首页新车卡片、插件卡片、新车一览、车型基础详情、规划车型、销量：

`展示页面 → 本项目 /api/new-car/* → 智能体共用的新车插件目录 → 146 /mcp/new-car → 服务端 PostgreSQL 正式表`

- 基础款型：`new_car_model`。
- 规划车型：`planned_new_car`。
- 销量：`new_car_monthly_sales`。
- 口碑接口及其数据维护本次不改动。
- 不再读取 8776 维护看板，不再由展示端直连基础款型 PG，不使用本地 JSON/演示数据回退。
- Token 仅在后台解析，沿用智能体的新车插件 URL、启用开关、超时及凭据设置；页面不持有凭据。

## 当前不是全量配置界面

车型详情展示基础款型字段，不读取本地 ODS 全量参数，也不读取 76 列周表。
全量配置可在维护电脑继续采集，后续独立校验、正式发布再接入，不作为本次展示改造前提。

## 刷新和口径

- 首页初始化、首页刷新、插件状态刷新重新调用新车 MCP。
- 新车一览进入页面、查询、重置重新获取基础款型和规划车型；分页/属性切换对本轮 MCP 结果做前端筛选。
- 点击车型详情再次读取 MCP，不以列表中的旧内容作为详情失败回退。
- 首页正式款型数与未筛选一览的款型数口径一致；品牌车型按 `(brand, model)` 去重。
- 最新月份款型按正式台账的 `launch_year` / `launch_month` 统计，不再显示维护端“待下发”指标。
- 业务基础台账为月份精度，列表/详情显示月份；日期检索按所在月份匹配，不把月初占位日当作真实上市日。
- 服务端尚无成功入库时间字段时明确显示“未提供”；批次、上市月份、查询时间都不等同于成功入库时间。
- API 禁用浏览器缓存；MCP 分页核对数量、记录键和进度，重复读取并比对完整内容检测更新中的结果；失败明确报错。
- 内容指纹仅用于本轮一致性核对，不能替代数据库事务快照。现有 MCP 无跨调用快照令牌，后续规模增长应升级为服务端聚合、数据库分页和版本校验，避免全量读取成本增长。
