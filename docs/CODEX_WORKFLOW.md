# Codex 工程执行流程（V1.2 历史参考）

> **V2.0 已生效：此文件以下内容保留为历史参考，不是当前执行约束。** 两个 AI 平等轮班、共享状态文件由当前执行者维护，也无需逐项跨 AI 审查。实际规则以 [项目 AGENTS.md](../AGENTS.md) 为准，状态见 [TASKS.md](../forecast-engine/share-files/TASKS.md) 和 [HANDOFF.md](../forecast-engine/share-files/HANDOFF.md)。无需每次读取本历史文件。

版本：v1.2；更新日期：2026-10-27（Asia/Shanghai）。适用于 myproject 全项目，首个试点为 forecast-engine。共同边界以 [AGENTS.md](../AGENTS.md) 为准；TRAE 专属规则位于 [.trae/rules/trae-collaboration.md](../.trae/rules/trae-collaboration.md)。本文件只补充 Codex 的执行步骤，不复制图谱、凭据、目录或浏览器规范。

## 1. 新会话、开工和恢复

1. 确认当前实际 Git 仓库根、启动目录及任务范围。桌面项目的主目录可设为 myproject，父 helloagent 保留为环境访问目录；这不是移动文件或更换 Python。
2. 实际读取根 AGENTS.md、本文件、相关共享 README、TASKS.md 以及对应 TASK.md、CODEX_REPLY.md、TRAE_REPORT.md。按磁盘最新版本恢复状态，不依赖旧聊天、历史规划或缓存总结。
3. 检查 Git 状态，区分既有已修改、已暂存和相关未跟踪文件；记录当前任务允许范围、依赖和交接对象。规则或交付文件不可见则明确指出，不假称读取、同步、合并或完成。
4. 读取任务清单中的工作区唯一写入方。TRAE 尚在该工作区写入时，Codex 仅只读检查，等待交接或使用独立 Worktree；文件不同也不构成并行写入许可。
5. 用简短开工说明列出实际已读规则版本、任务版本、允许范围和验证计划。需要留存时写入自己维护的任务记录，不创建每会话重复日志或签字文件；没有实际读取不得填写确认。

已分派的开发/集成任务必须有 TASK.md。新任务先向用户提出方案，获得明确确认后才建立编号/目录和任务要求，再改业务代码；当前任务内继续修复或补证时更新原 TASK.md 版本，不另起编号。用户要求先规划的阶段只输出方案。纯只读咨询或明确授权的文档维护可直接按限定范围执行并留下相称证据，不为此新建空管理流程。

## 2. 规划及分派

- Codex 对整体技术架构、任务拆分、统一分派、跨模块协调和集成验收负责；用户保留重大决策和业务最终验收。
- 分派前核实 TRAE 已承担及已完成的成果、当前源码和证据，不重复安装、下载、封装或另建同类实现。Chronos-2 模型侧归 TRAE，业务适配与评价归 Codex，具体边界见当前任务。
- 每项任务指定唯一执行负责人、允许文件、依赖、输入输出、验收标准、任务版本和明确交付方式。依赖未就绪时先协调，不把规划视为已分派。
- 新编号和新任务目录必须经用户明确确认。当前任务未完成不得自行另起任务，把交接阶段通过误写为整项结束，或通过拆号迁走阻断问题。当前 CHRONOS-001 内继续完成 T001/C001，阶段通过与整项验收分开记录；未经用户确认不创建 CHRONOS-002 等新任务。
- 公共接口、数据库结构、共享配置、依赖环境、跨模块架构和重大业务变更先协调。业务口径、重大架构、原有预测功能改变及无法协调的优先级冲突提交用户；普通技术问题按职责解决，不反复要求用户裁决。
- 共享文件异步反馈，不创建 AI 通讯系统、后台轮询或未获授权的定时任务。

## 3. 文件归属和并行边界

Codex 独占维护 TASKS.md、各 TASK.md、CODEX_REPLY.md 和经协调的接口契约。TRAE_REPORT.md 由 TRAE 唯一维护，Codex 只读；仅任务初建时可按用户授权生成空模板，不代写成果。TRAE 专属规则已有内容不得因重新初始化而覆盖。

同工作区只允许一个 AI 写入。交接记录包含当前写入方、任务、允许范围、停止写入/释放状态、下一接手方；接手方实际读取后再执行。TASKS.md 是协调记录，不是操作系统文件锁，不能据此声称另一进程已被技术锁定。

真正并行需独立分支和 Worktree。创建前核实相关源码已进入可复现 Git 基线，不能从缺少未跟踪 forecast-engine 的 HEAD 开出空能力副本。模型环境升级、数据库和端口等仍需单独协调；Worktree 不隔离这些资源。

## 4. 实施及代码审查

1. 结构性探索执行 [已有图谱流程](codebase-memory-workflow.md)：限定实际项目根，核查覆盖及新鲜度，读关键源码。工具失效时记录失败和源码回退范围，不宣称全量影响已核实。
2. 对照任务范围检查实际 Diff、暂存及未跟踪文件，区分本任务和他人改动。不以工作区全部 dirty 文件作为某一 AI 的成果，不覆盖或回滚已有工作。
3. 接收 TRAE 报告后实际读取其引用的代码、脚本、日志及产物，核实路径、哈希或版本对应。缺文件或代码未同步则明确记录，不要求用户复制聊天代替磁盘证据。
4. 检查实现、接口、输入输出、异常处理、数据泄漏、隔离和副作用；必要时核对相关调用点。先读复验脚本，避免覆盖原始证据、写业务库或意外触发下载、外部 API 或服务重启。
5. 发现问题使用原问题编号持续记录到 CODEX_REPLY.md，写明状态、当前处理负责人、原因判断、修改要求和验证条件。Codex 不在 TRAE 正负责的文件中代修；超范围工作先协调任务要求。

## 5. 测试与验收

- 依据 TASK.md 原定标准选择有意义的验证；模型断言、API、回测及页面各验证对应层次。静态检查、mock、真实运行及业务验收必须分别标明。
- 核对测试命令、实际解释器、输入版本、断言、退出码和真实输出。退出码 0 或模型回答“成功”不自动代表通过；未执行、缺证据、失败项和环境限制明确记录。
- 优先复用可追溯证据，对重要缺口独立复验；新证据用唯一目录，保留原始结果。修改后执行与影响相称的回归，避免仅为重复验证而无理由重跑全部任务。
- 任务必需验证未实际通过，状态保持进行中、待审查或阻塞；不得标记已验收，不得为通过而事后修改验收标准。
- 资料交接完成只代表约定材料及既有成果已核验，不代表模型健壮性、真实数据精度、业务集成或发布通过。各结论分开写明；开放的阻断问题必须阻止对应功能验收。
- CHRONOS-001 的 R1 仅为交接阶段结论；模型健壮性和 T001 的当前状态以任务清单及 Codex 回复为准，不借规则更新改变历史结果。原有市场预测不切换，Chronos-2 成果保留。

## 6. 三处同步、反馈和收尾

收到交付或完成审查后，由 Codex 同步：

1. CODEX_REPLY.md：追加本轮审查、证据、结论、问题负责人和下一步，保留历史。
2. TASK.md：追加审查摘要、验收范围和回复/证据索引；保留原要求及验收标准。范围变化明确版本和原因，不改成另一套状态台账。
3. TASKS.md：更新任务整体状态、依赖、交接对象和工作区写入交接状态；它是任务状态的唯一来源。

TRAE 在自己的报告回复；Codex 在相关会话开工、用户触发、交接及集成前读取。一般技术问题按职责处理，需要用户决定时列选项、影响和建议；未读不等于接受，任务已验收不自动关闭独立问题。

收尾说明本轮实际变更、验证结果、未测项、未关闭问题和下一步。未经用户授权不提交、推送、合并或部署，不关闭月报浏览器、不清理业务数据；具体工程保护规则复用 AGENTS.md。离开前更新当前写入状态，不默认对方已接手。

## 7. 跨会话验证及能力边界

- 本文件由根 AGENTS.md 强制引用；从外层 helloagent 启动时先由其简短 AGENTS.md 路由。不要把进入子目录或链接存在当作启动时已自动加载。
- 在桌面现有项目“编辑项目”中将 myproject 设为 Primary，可保留 helloagent 为附加目录；保存后验证新任务的实际目录，当前对话保留其记录的目录也需显式使用实际仓库根。
- 文件落地后先检查链接、规则一致性、目录登记和受保护文件哈希。另开不继承旧历史的新会话做只读验证：要求列出已读取的规则来源/版本、当前任务及允许写入方；检查真实工具读取轨迹，不以自述为证明。
- 再以只读情景检查：无测试证据不验收；TRAE 正在同一工作区写入时不并行写；不编辑 TRAE_REPORT.md、不重复安装既有模型。不得为验证而真的执行禁止动作。
- 当前会话的静态检查不能代替新会话加载验证，也不保证任何 AI 永远遵守；用读取轨迹、限定范围 Diff 和实际测试持续核对。发现遗漏先纠正，不伪造既往读取或通过记录。
