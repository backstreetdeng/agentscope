# 新车板块数据流梳理

核验日期：2026-10-12。范围：代码与现有只读接口；不修改功能、数据库、采集脚本或部署。实时读数仅代表本次成功请求，复核中出现连接异常，不代表持续健康。

## 核心结论

目前不是统一的新车消费链路：首页统计依赖本地8776监测服务，一览与详情附属模块由7860直接查询146 PostgreSQL，智能体插件调用146新车MCP。两组正式表与MCP已在一次成功核验中对账一致，但首页不能据此称为同源。

## 页面与接口

| 使用位置 | 浏览器请求/行为 | 后端来源 | 刷新与失败行为 |
| --- | --- | --- | --- |
| 首页新车卡片 | `/api/new-car/dashboard`，再尝试浏览器直连8776 | 7860转发到 `127.0.0.1:8776/api/dashboard` | 初始化加载一次；失败保留HTML中的2111、553、356、2026-09-12；本次代理返回502 |
| 新车一览 | `/api/new-car/list` | 146 `new_car_model` | 一次性全量加载；筛选、车型聚合、每页50条都在浏览器；失败回退16条内置示例 |
| 规划新车 | `/api/new-car/planned` | 146 `planned_new_car` | 一次全量加载，浏览器每页30条；失败显示不可用；不跟随上方上市款型筛选 |
| 车型基础详情 | 在同一HTML隐藏一览、显示详情 | 浏览器已有 `ROWS`，按品牌＋车型聚合同车型款型 | 点击详情不重新请求基础档案；图片只有问界M9、理想i8两个本地映射 |
| 详情销量 | `/api/new-car/sales?model=...` | `new_car_monthly_sales` | 点击详情重新请求；缺失显示空状态，不补模拟销量 |
| 详情口碑TOP5 | `/api/new-car/reputation?model=...` | `new_car_reputation_taxonomy_summary` | 点击详情重新请求；缺失显示空状态 |
| 口碑标签树/原文 | `reputation-tree`、`reputation-reviews` | `new_car_reputation_review_tag` | 下钻查询；原文接口数据库侧分页 |

首页“刷新”目前只刷新政策和权益，不调用新车统计。新车插件的“查看/配置”按钮没有接上新车明细路由，当前主要触发卡片选中切换。

## MCP

有效地址：`http://192.168.3.146:8790/mcp/new-car`。部署配置为网关转发到 `new-car-mcp:8813/mcp`，查询PostgreSQL。

现有7工具：状态、上市款型检索、规划新车检索、单款型详情、上市日历、车型销量、车型比较。详情按车型名查询时只返回一款；与网页按品牌＋车型展示所有款型的行为不同。检索仍是数据库取匹配全集后在Python分页，不是SQL LIMIT/OFFSET分页。缺网页已有的新车属性筛选、车型分组统计、概览聚合、Excel导出，以及来源/版本/最后成功入库时间的完整状态契约。口碑已有独立MCP，应复用其能力而非复制到新车库。

## 数据来源与维护

已找到的实际维护代码不是网页所宣称的即时官网采集链路：

1. `tools/new_car_sync.py`：默认业务文件为“2026.1-8新车数据TO晓亚冰雨_202609.xlsx”，写入 `new_car_model`。款型ID为主键，源内去重，ON CONFLICT更新；批次默认202609。仅有年/月时将上市日设为当月1日，因此不能把该字段一律解释为精确官方上市日。
2. `tools/planned_new_car_sync.py`：默认“！0716结果更新版本-2026新车跟踪（含已上市+未上市）.xlsx”的“规划新车-0716”工作表。按批次＋行号存储；同批次先删除后重写，旧批次保留。查询没有只取最新批次；换批次导入同一车型存在重复风险。
3. `tools/new_car_detail_sync.py`：独立目录“乘用车-新车明细板块-0927”中的销量、汽车之家口碑、懂车帝口碑和V1.0标签字典。维护8款指定车型；更新时替换这些车型的销量、标签摘要与标签原文记录。
4. 早期 `tools/new_car_reputation_sync.py` 写 `new_car_reputation_summary`，当前详情读取的是后续taxonomy表；不能误把早期表当成页面当前来源。

本次没有执行这些写入脚本。未发现这条展示链路有可验证的每小时采集/入库调度。真实运行频率、维护者、8776背后数据库与采集项目位置，需要维护端继续提供或核验；不能根据页面宣传文案认定。

新车插件“工信部/企业官网/媒体首测”“近36个月487款”“214字段”“22分钟前”都是静态文字；当前已上市基础表导入定义为14列，价格和详细配置不在当前基础档案返回字段中。现阶段不能称为完整配置库。

## 建议统一方式（尚未实施）

```text
独立采集/维护端 → 校验与入库 → 146正式数据库
                               ├→ 新车MCP → 7860展示适配层 → 首页/插件/一览/基础详情/导出
                               └→ 口碑MCP → 7860展示适配层 → 车型口碑与证据下钻
```

首先明确“款型/品牌车型/规划车型”的统计单位与上市日期精度；确定8776是否有尚未进入正式库的独立数据。之后补齐MCP概览、属性筛选、车型聚合、全部款型详情、SQL分页、导出和元数据，再统一页面消费路径。去除静态/示例回退；错误、空值与真实零值分开。维护脚本与智能体职责保持分离；成功入库时间不能用数据批次或工具发现时间冒充。表结构调整如有需要，另行确认，不在本次梳理中执行。
