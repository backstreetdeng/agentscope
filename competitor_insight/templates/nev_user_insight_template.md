## 0. 模板标识

| 项 | 内容 |
|---|---|
| 模板名称 | 新能源用户洞察档案模板 |

## 2. 填写说明与合格标准

原则：**单用户档案只写这一个受访者的事实与原话**；聚合结论（"XX% 用户""多为 22-33 岁"）属于报告层，不进档案。

### 2.1 基本信息与画像

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 受访者编号 | 调研执行方分配的唯一编号，用于回溯源文件与录音 | 非空、与调研名单一致、不重复建档 |
| 年龄 | 实际周岁 | 18–70 整数；不写区间（区间留给聚合） |
| 性别 | 受访者自述 | 男/女枚举之一 |
| 婚姻与家庭状态 | 当前婚姻与家庭结构 | 枚举之一；有孩需能说明孩子年龄段（写入 life_values 或备注） |
| 个人收入区间 | 个人年收入区间，用于判断预算合理性 | 枚举之一；填「不便透露」须有其他预算字段佐证 |
| 学历 | 最高学历 | 枚举之一；未问到时留空，不臆测 |
| 所属行业 | 具体行业或职业 | 写具体行业/职业；「行业分散」是聚合结论，不能作为单条取值 |
| 生活状态与价值观 | 生活节奏、消费观、情绪价值偏好 | 至少含「生活状态」「消费观」两项，且各有一句可引用的事实或原话 |
| 兴趣爱好 | 可多选，用于解释用车场景与内容偏好 | 至少 1 项；选「其他」须在 life_values 补充 |

### 2.2 购车关注与决策

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 购车阶段 | 本次是首购/增购/换购 | 枚举之一；增换购须能关联 user_source 前车信息 |
| 购车预算区间 | 实际可接受裸车价区间 | 枚举之一；与 price_anchor 不矛盾 |
| 品牌关注与要求 | 对品牌的关注程度与具体要求 | 须写「关注度」+「具体要求」两层；只写「不在意品牌」视为未合格 |
| 购车关注因素 | 受访者主动提及的关注因素 | 至少 2 项；来自受访者原话，非访问员归纳 |
| 关注因素 TOP5 排序 | 按重要性降序的前五项 | 恰好 5 项、顺序明确；与 attention_factors 不冲突 |
| 价格锚点 | 心理价位（万元） | 数值保留 1 位小数；须有原话或明确选择依据 |
| 流失红线 | 一旦触发就放弃购买的条件 | 至少 1 条具体条件（价格/试驾/交付/配置）；不能只写「看情况」 |

### 2.3 用户来源与增换购

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 前车能源类型 | 前车动力类型；首购填「无前车」 | 枚举之一；与 purchase_stage 一致 |
| 前车级别 | 前车级别，口径 A00/A0/A/B/C+ | 枚举之一；不确定留空，不猜测 |
| 前车品牌 | 前车具体品牌与车型 | 品牌名可核验；只写「合资车」不合格 |
| 前车品牌属性 | 自主/合资/豪华，对齐报告占比口径 | 枚举之一；与 previous_brand 不矛盾 |
| 对比车型清单 | 实际对比过的车型，可含本品 | 至少 2 个车型、名称可识别；不写「几个竞品」 |

### 2.4 本竞品对比与首选

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 核心对比车型 | 最终决策时最主要的对比车型 | 唯一车型；须出现在 considered_models 中 |
| 首选车型 | 对比后的第一选择 | 唯一车型；未决定写「未定」并说明还差什么信息 |
| 战胜原因 | 首选车型胜出的原因 | 至少 1 项，且 win_reason_detail 有对应原话 |
| 战胜原因说明 | 对战胜原因的具体说明与原话 | 每个被选中的原因至少一句说明或原话 |
| 竞品胜出逻辑 | 首选不是本品时，竞品靠什么胜出 | 首选为竞品时必填；须落到具体卖点组合，不能只写「更好」 |

### 2.5 满意度与进攻方向

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 总体满意度 | 对首选/已购车型的满意度 | 0–10 的整数或 1 位小数；与满意/不满意点不矛盾 |
| 满意点 | 明确认可的点 | 至少 1 条，每条含具体场景或体验；不写「整体不错」 |
| 不满意点 | 明确抱怨的点 | 至少 1 条；区分「产品缺陷」与「个人偏好」 |
| 本品进攻方向 | 由不满意点推导的本品机会 | 与本条不满意点一一对应；无对应关系留空 |

### 2.6 信息渠道

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 认知种草触点 | 第一次知道该车型的渠道 | 至少 1 项；能说出具体内容或账号类型 |
| 对比研究触点 | 做参数与口碑对比的渠道 | 至少 1 项；与认知触点区分 |
| 决策成交触点 | 最终促成决策的触点 | 至少 1 项；涉试驾须说明车型与时长 |
| 内容形式偏好 | 更信赖的内容形式 | 至少 1 项；选「其他」须说明具体形式 |
| KOL 影响程度 | KOL/达人内容对决策的影响 | 枚举之一；填「高/中」须举例 |

### 2.7 本品吸引力

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 本品吸引点 | 最吸引受访者的能力项 | 至少 1 项；与 attention_factors 的对应关系可解释 |
| 吸引点说明 | 具体配置或体验依据 | 每个被选中的吸引点至少一句依据，可引用配置名 |
| 网约车标签影响 | 网约车同款是否影响购买意愿 | 枚举之一；填「负面」须说明具体顾虑 |

### 2.8 转化机会与风险

| 维度 | 填写说明 | 合格标准 |
|---|---|---|
| 转化触发条件 | 在什么条件下会转而购买本品 | 至少 1 条可执行条件（价格/配置/权益/交付）；不能只写「价格合适」 |
| 流失风险 | 导致放弃本品的主要风险 | 至少 1 项；与 churn_redline 一致 |
| 原话证据 | 支撑关键结论的受访者原话 1–3 句 | 加引号、不改写为访问员总结 |
| 访谈日期 | 深访执行日期 | YYYY-MM-DD，不晚于建档日期 |
| 访问员 | 执行访谈与整理档案人员 | 填写姓名或工号，便于回溯 |

## 4. 机器可读版本

- 文件：`competitor_insight/templates/nev_user_insight_template.json`
- 结构：`template_id` / `name` / `version` / `status` / `scenario` / `source_baseline` / `groups[]` / `dimensions[]`
- 每个维度字段：`id`、`name`、`group`、`type`、`required`、`description`、`qualified`；`enum`/`multi` 额外带 `options[]`
- 后端读取方式：按 `dimensions` 校验单用户档案完整性（必填缺失即不合格）、按 `type` 做取值校验、按 `group` 汇总回 P 章节。
- 前后端一致性：本 md 的维度表与 JSON 的 `dimensions` 必须同源同步；以 JSON 为唯一事实来源，本文件为可读镜像。
