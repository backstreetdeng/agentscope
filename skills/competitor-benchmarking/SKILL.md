# 竞品对标（Competitor Benchmarking）

## 0. 运行边界

- 本 Skill 为**语义层规则**，运行载体为竞品对标研究引擎（`utils/benchmark_research_dag.py`，机制复制自月报 ResearchDAG、独立演进，月报零改动）：模型只提问与解读，工具回执才是证据；模型文字不是完成证据。
- 内部销量等业务数据禁止传入任何联网搜索/精读工具。
- L1 快问快答直接答复，不产出矩阵。
- 引用体系：所有事实带 `receipt_id`（回执 ID），不用无回执的陈述锚定结论。

## 1. 任务类型路由

| 输入 | 任务类型 | 默认深度 |
|---|---|---|
| 指定目标车型（新车/改款/竞品） | S1 对标 | L2 |
| 发布会事件 / 竞对动作 | S2 态势 | L2 |
| 工信部公告批次 | S3 巡检 | L1（预警）→ 需要时升级为 S1 |

深度分级与预算：

| 深度 | 范围 | 预算上限 |
|---|---|---|
| L1 | 单一事实核验 | ≤3 次检索 |
| L2 | 标准对标（矩阵 8–12 维度） | ≤10 次检索、≤28 研究节点 |
| L3 | 深度对标（多维 + 格局分析） | Phase 1 不启用 |

## 2. 四段工作流

### 2.1 接收与路由

1. 识别输入类型（S1 / S2 / S3）与目标对象。
2. 校准深度（L1–L3），据此设定矩阵维度数与取证预算。
3. 建立任务图初始节点（目标、成功标准、依赖）。

### 2.2 迭代取证循环（核心引擎）

```
竞品池假设 → 三源取证 → 交叉验证 → 池修正 →（循环或终止）
```

**工具优先级（严格遵守）：**

1. `miit_*`（P0）：硬参数唯一锚——纯电续航、整备质量、能耗、电池能量
2. `reputation_*` / 汽车情报知识库（P2）：定性口碑、评测、技术拆解
3. `web_search_local` → `web_search_exa` → `web_search_tavily`（P1/P2）：上市权益、变动售价、交付周期、OTA 动态；搜索工具依次尝试，全部无效则声明无法获取，不循环重试
4. 拿到 url 后再精读：`web_reader_local` → `web_reader_firecrawl`（仅前者失败时用）

**每轮显式产出**：已验证事实（带 `receipt_id`）+ 缺口清单 + 下轮理由。

**终止条件**（满足其一）：核心维度 ≥3 独立来源；剩余缺口可忽略；预算耗尽（必须显式声明，不得静默降级）。

### 2.3 冲突处理

- 来源一致 → 带 `source_tier` 综合进矩阵。
- 冲突 → 三型分治（口径 / 时效 / 立场，规则见 [references/evidence-rules.md](references/evidence-rules.md)），双边呈现，禁止武断站队。
- 数据不足 → 标记 `insufficient`；**缺口即发现，不算失败**。

### 2.4 交付

- 对标矩阵：模板与验收清单见 [references/benchmark-matrix.md](references/benchmark-matrix.md)，契约见 [assets/matrix-schema.json](assets/matrix-schema.json)。
- 战略 So What：规则见 [references/so-what.md](references/so-what.md)。
- 验收：`scripts/validate_matrix.py` 通过才算交付；失败项结构化反馈进入修复循环。

## 3. 信源分级与标注纪律

| 层级 | 工具前缀 / 来源 | 用途 |
|---|---|---|
| P0 | `miit_*`（款型配置信息） | 硬参数唯一锚 |
| P1/P2 | `web_*`（联网检索与精读） | 市场动态、价格、OTA |
| P2 | `reputation_*` / 知识库 | 定性口碑、技术拆解 |
| P3 | 一般网络参考 | 仅作线索，不进矩阵 |

单元格标注状态：`confirmed`（≥3 独立来源）/ `majority` / `disputed` / `single_source` / `insufficient` / `na`。互相引用不算独立来源。

## 4. 红线规则

1. 硬参数（续航/整备质量/能耗/电池能量）不用申报值以外来源替代；宣传值仅作佐证并标注口径。
2. 价格阶梯分列（指导价/先享价/限时价/经销商价），不合并为单值。
3. 禁止编造数据；缺失标 `na`。
4. 推断与事实分离：事实进矩阵，判断进 So What 且必须带置信度。
5. 同工具同参数不重复调用（引擎签名去重兜底，规划器不得故意绕过）。
6. 完成证据 = 任务图 + 回执 + 验收器通过，不是模型陈述。
