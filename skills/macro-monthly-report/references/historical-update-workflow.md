# 历史滚动更新与主题句：5—7月样例学习结果

本规则来自用户提供的三份内部报告的结构、文字和原生图表，非官方经济数据核验。
历史更新已由独立historical_update模式实现；完整正式交付以真实任务通过全部验收为准。

## 一、月份与信息边界

独立记录 `report_month`、`issue_month`、`outlook_month`、`cutoff_date`。
8月报告正文使用8月实际观测，发行月通常为9月，末页前瞻9月；具体截止日以用户任务为准。
GDP延续最新已发布季度，月度概览非季度发布月份为`--`，不制造8月GDP。
周度/日度图采用本次报告允许的截至日，分别注明更新至日期。
7月样例高频图含8月观测、政策页含8月17日事件，证明报告月份与信息截至日不能合并。
对历史复盘：可以用截止日前已发布的修订，不能以之后数据解释当时决策。
对今天制作的回顾报告：后续修订可用，但明确版本，不能混入当时预测的训练信息。

## 二、报告骨架与模板漂移

共同骨架：封面→总览摘要→全球形势→国内数据概览/高频→实体经济→物价→信贷货币→汽车→政策→下月前瞻→结尾。

| 内容 | 5/6月页 | 7月页 |
|---|---:|---:|
| 摘要、全球PMI、数据概览、高频、GDP、PMI | 2、4、7、8、10、11 | 相同 |
| 消费者/企业信心 | 12 | 已删除 |
| 工业、投资、社零、消费结构、地产、房价、进出口 | 13—19 | 12—18 |
| CPI、PPI | 21、22 | 20、21 |
| 贷款、社融、M1/M2 | 24—26 | 23—25 |
| 汽车 | 28 | 27 |
| 财政货币、政策前瞻 | 30、31 | 29、30—31 |
| 下月预测表 | 32 | 32 |

5/6月均33页37个原生图表，7月33页36个原生图表。7月高频页由4图变5图，
删除信心页2图，增加政策页；总页数相同不代表对象映射兼容。
同一图表文件名和同一shape编号也不证明同一指标，按页主题、图题、系列名、口径和单位映射。
7月作为最新结构参考，5/6月用于比较写作和历史变化。当前包的reference虽为7月题名，
其哈希及图表结构与新提供7月样例不同，切换必须重新建立契约。

## 三、历史数据不是每次从零重采

建立包内历史底库，每条记录保留：文件哈希、月份版本、页/对象、指标ID、系列、统计期、
原值、单位、当月/累计/同比/环比、数据来源标注、提取位置、核验状态。
从原生图表缓存与内嵌工作簿读取，概览表和正文用于交叉核对，不从图片估算数值。
识别Excel序列日期，按统计日期排序；不少图表倒序排列，末尾数组元素不是最新值。
名称类别图、雷达图与按年季节图不能套用月份追加算法。

允许用户提供历史记录作为已知历史展示，标注 `user_provided_history`，不冒充新采官方事实。
本次新增月份、上期比较和所有标题涉及的数据必须经过核对；历史不是无条件可信。
相同指标同一期多份报告有差异时保存全部版本，先查修订说明，再查原始发布；
不能静默取均值，也不能笼统以最新文件覆盖。无冲突历史不要求每次重新联网逐点采集。
遇到冲突，仅补采该指标/该期。预测训练用到的历史另按训练证据要求核验。
已有forecast和public_draft流程的验收约束不因本规则自动放宽。

本次示例冲突（仅识别内部不一致，未判定哪个值为官方正确值）：
- 5月社零页写4月1.5%，7月概览及5月预测表写4月0.2%。
- 5月核心CPI正文1.1%，6月正文1.0%却称持平：比较措辞应重新计算。
- 7月摘要CPI环比持平，7月CPI正文环比下降0.1%。
- 7月概览把PMI写成“同比/%”，应区分PMI指数水平与同比增速。
- 7月汽车图题“中汽协汽车销量”与来源“乘联分会”存在口径疑点。
- 6月GDP需求拉动2.1+1.7+0.8=4.6，与累计4.7差0.1；先检查发布与舍入，不能强行调平。

## 四、不同图表更新方式

| 图形 | 更新行为 | 同步修改 |
|---|---|---|
| 月度时间序列 | 加入新期，原窗口若固定则移除最旧期 | 日期范围、公式、缓存、内嵌单元格、末点标注 |
| 季度GDP | 新季度发布才新增 | 当前季度与累计口径、正文月份 |
| PMI雷达 | 替换成本月和上月快照 | 系列日期、分项一一对应、50荣枯线 |
| 消费分类 | 同类别比较本月/上月 | 类别名称、同比/环比、排序和涨跌方向 |
| 贷款/社融季节图 | 上年全年保留，本年补至报告月 | 本年未发布月空白；不能0填充 |
| 汽车年内图 | 确认总车/乘用车、批发/零售后追加 | 辆→万辆只换算一次；同比同口径 |
| 高频图 | 补截至日内的新日期 | 每条序列各自最新日期，不能伪装月均值 |
| 概览表 | 增加报告月，保持同表窗口 | 与正文/图表共用事实，变化箭头自动算 |
| 下月前瞻表 | 列本月、上月实际及下月预测 | 独立预测期、方法/假设、方向 |

先写数据，再算变化，再写结论，最后更新摘要。不能全局替换月份后沿用旧判断。
当前公共草稿会清空未验证旧数据，适合明确选择草稿的任务，不适合代替历史滚动更新。

## 五、主题句写作规则

标题说出本页最重要变化/结构矛盾，正文用“总量事实→结构证据→解释或业务含义”支撑。
通常标题一句、正文一至两段，适应原文本框；具体字数按版面实测，不靠无限缩小字号。
不是“8月：某指标某数值”的数据播报，也不是每页固定“稳中向好”。

| 页主题 | 样例原句/写法 | 可复用逻辑 |
|---|---|---|
| 6月PMI | 制造业PMI回升至扩张区间，中型企业景气明显改善 | 总体跨越50边界＋分规模改善 |
| 7月工业 | 工业增加值增速回落，高技术制造业保持较快增长 | 总量放缓＋亮点韧性 |
| 6月社零 | 社零增速转正，消费修复仍呈结构性特征 | 改善信号＋约束条件 |
| 6月PPI | 同比升至4.1%，但环比转降显示输入性压力缓和 | 区分同比与环比，不混写“全面回升” |
| 7月社融 | 新增社融1.40万亿元，政府债券成为主要支撑 | 总量＋融资来源结构 |
| 汽车 | 内需同比表现持续弱于出口市场 | 需要内销与出口两组证据，不能只凭总销量 |

先构建每页事实包：当期值、上期值、百分点变化、同口径结构项、连续趋势、阈值、来源。
模型基于事实包生成主题句和解释，确定性规则负责数值、方向、时期、单位和排名检查。
每个判断挂到事实ID；“因为/带动/拖累/贡献”需要贡献计算或来源解释，不能仅凭相关走势。
只有分类增速不能证明对总量的贡献，更不能称“主要拖累”除非有权重/贡献证据。
“高基数”“季节性”“政策见效”“外需拉动”需要对应证据；未证实时用可能/仍需观察，或删去。
“创新高/历史低位/超预期”分别需要覆盖的历史窗口、基准/一致预期，不能靠标题模仿。
摘要从完成的数据页提炼供需、价格、信用、汽车和政策，不另写一套数字。
政策页先列截至日前原文与发布日期，再区分实际政策与传导判断；不能复制上一月政策因果。

## 六、网页实现与验收清单

下一版新增独立历史更新模式，不能仅改SKILL文本或把mode字符串改名：
1. 注册整个历史资源包，所有路径相对包根，复制到隔离运行目录；保存包哈希。
2. 建立新7月结构的契约，按含义映射，保留现有forecast的兼容路径。
3. 历史底库预检查→只检索新期及冲突期→本月图表/概览→事实包→主题句→摘要/政策→下月前瞻。
4. 预测只在前瞻页执行；有足够核验历史才给数值，不能把上月预测当本月实际。
5. 持久化每阶段检查点，失败只恢复未完成指标；进度显示历史复用、新采、冲突、未发布数量。
6. 缺项区分未发布、采集失败、精确口径缺证，按问题补采；草稿必须是独立显式交付选择。
7. 检查每个图表缓存与引用的内嵌工作簿单元格一致、无外部链接、文本图表表格可编辑。
8. 数字与标题/正文/摘要/方向一致，政策不越截至日，8月正文不混9月预测。
9. PowerPoint重开和逐页渲染通过；真实网页8月任务产物独立验收通过后，才标记“已接入”。

网页请求使用 `mode=historical_update`、`delivery_mode=formal`；公开草稿仍是独立旧版流程。
当前程序只把完整取证的正式月报发布到正式下载；不完整候选PPT保留在运行目录供修复。
Python需要python-pptx、openpyxl、lxml；最终版面验收需要可用的Microsoft PowerPoint。
使用示例：
“参考5—7月优秀月报，生成2026年8月宏观经济分析报告。以7月结构为底稿，
复用经过冲突检查的历史序列，补入8月可核验实际；正文形成主题句与分项解释，
末页单独展望9月。信息截至日按任务指定。保留原生可编辑图表、表格和文字，
内部自动建台账，未通过数据与版面验收不得标记正式完成。”
