## 本次迭代重点（用户校准：时间准确性 / 技术实质 / 企业要闻边界 / 排除销量财报）

> 以下四条为本轮用户复核终版周报后提出的硬性要求，**每次生成前必读、必执行**：

1. **时间准确性（所有板块，高层动态最严）**：以「事件真实发生日 / 任免生效日 / 公告日」为锚，绝不为「报道发布日」所惑；旧闻翻出或同一事件的重复报道（尤其高层变动常有「天眼查工商变更 → 官方公告 → 媒体解读」多轮），只要最早变动时间不在本周窗口，**一律不收**，且不重复收录上周已报过的同一条。
2. **零部件 / 新能源技术要看「实际落地的技术」**：在盖世资讯选条时，优先收录有产品 / 技术实质落地信号（量产、投产、定点、送样、明确参数、上车规划）的资讯；纯战略合作 MoU、融资 / 增资、无技术参数的「合作框架」空话稿，以及仅发论文、无产业化路径的实验室成果，降权或跳过，不要当行业技术进展堆入。
3. **企业要闻边界**：① 某款具体车型的上市 / 预售 / 首发 / 车展亮相 / 官图，一律归「九、新车上市」板块（按全新判据筛选，非全新则连同本板块剔除，不要回流凑数）；② 企业在海外的建厂、出口基地、海外上市、海外市场专属车型、出海合作等纯海外视角资讯不收录。
4. **⚠️ 销量 / 财报 / 月度产销数据一律不收录（2026-09-05 用户指令，永久生效）**：企业销量、月度交付量、季度 / 半年 / 年度财报、当月乘用车销量、行业月度产销 / 渗透率 / 份额 / 利润率等**周期性数据发布类新闻**，所有板块（含企业要闻、行业动态、摘要）均**不收录、不作摘要**。企业要闻只收非销量类动态（合作、投资、战略、技术平台、产能 / 基地、人事、组织调整等）；行业动态只收产业级事件与政策落地，不收产销数据发布。
5. **⚠️ 溯源与跨周去重（强制，2026-09-17 用户指令）**：
   - **生成前必读 `references/coverage_log.md`**：该台账逐期记录已报道条目标题（含事件日期与来源链接）。凡本周候选条目**标题或事件已出现在台账中**（含上周 / 更早周已报过的同一条、或旧闻的后续跟进 / 综述稿），**一律不收**；只认「事件真实发生且首次进入本周窗口」的增量。
   - **每条必须带来源 URL**：写入 `report_data.json` 的 `source` 字段（见文末 JSON 结构），用于内部核对与溯源。
   - **生成后回填台账**：把本周全部条目（期次 / 板块 / 标题 / 事件日期 / 来源）追加到 `coverage_log.md`，保证下周可去重。
   - **配套产出来源文档**：运行 `scripts/gen_sources.py` 生成 **《中国汽车产业周度资讯快报2026.MMDD-MMDD_来源.docx》**（另一条目标题 → 来源清单），与正报一并交付，便于你逐条核验出处。
6. **⚠️ 用词准确度（首秀 / 首发 / 全球首发 / 亮相等，2026-09-17 用户指令）**：
   - 使用「首秀 / 首发 / 全球首发 / 首次亮相」等**最高级 / 首次**表述前，**必须联网核实**该车型 / 技术确为**首次公开亮相**——尤其跨车展场景（如某车已在成都车展展出，则青岛车展只能写「亮相 / 参展 / 展示」，不得写「首秀 / 首发」）。
   - 核实手段：检索「车型名 + 车展 / 亮相 / 首发 / 上市」历史；同时比对 `coverage_log.md` 中是否已有该车型的更早亮相记录。
   - 无法确认「首次」的，**降级为「亮相 / 参展 / 展示 / 公布」**等中性、无歧义表述；全篇用专业克制语言，避免夸大与歧义。
   - 同理：具体参数、技术落地节点等，凡无权威来源支撑的，宁缺毋写或注明「据 XX」。

## 通用规则（所有板块通用）

1. **精炼概括**：每条资讯 80–200 字，含具体日期与数据，客观纪实，不发挥、不评论。
2. **JSON 安全**：正文中的引号一律使用中文弯引号 `""`（U+201C / U+201D），绝不用 ASCII 直引号 `"`，否则会破坏 JSON 解析；若已混入，用 `fix_json.py` 修复。
3. **⚠️ 日期过滤与「真实时间」核验（高频踩坑点，所有板块通用，高层动态尤其严格）**：
   - 只收录**事件真实发生时间落在日期范围内**的资讯；以「事件 / 任免 / 公告 / 投产 / 上市 / 签约的实际日期」为准，**绝不能以新闻报道的发布日代替事件日**——若某报道发布日在窗口内，但其描述的事件实际发生在更早的窗口外（旧闻翻出 / 重复报道），**一律不收**。
   - **高层动态时间核验（必做）**：以「任免公告日 / 董事会决议日 / 新职务生效日」为锚点，逐一核对该高管变动是否真正发生在本周窗口内。同一人事变动常有多个媒体在不同时间重复报道（先有天眼查工商变更、后有官方公告、再有媒体解读），**只认「最早且权威的变动时间」**；若最早变动时间已不在本周窗口，即使本周出现了新的解读 / 回顾稿，也**不得纳入**，并避免与上周已收录的同一条变动重复。
   - 其他板块同理：遇到「事件发生在窗口外、仅本周有跟进 / 综述稿」的情况，跳过；确属本周延续事件（如上周签约本周落地），正文可注明原日期，但主体须在本周窗口内。
4. **来源优先**：优先官方/权威来源（政府网站、车企官方、盖世汽车、汽车之家、第一电动、证券时报等）；带来源链接用于内部核对，正文不必堆砌链接。
5. **只关注高价值信息**：销量高/影响力大的品牌与事件优先；边缘品牌不单独成条。**销量 / 交付 / 财报等周期性数据新闻一律不收（硬规则 4），也不作摘要佐证**。

6. **⚠️ 事件状态筛选（已发生优先，预告可少量点睛）【高频踩坑点】**：正文**优先收录本周日期范围内已实际发生**的事件——正式上市 / 预售开启 / 签约 / 人事任免 / 工厂下线 / 量产 / 定点（财报发布、销量 / 交付数据不在此列，见硬规则 4）。

## 九、新车上市 → 九大章节「九、新车上市」

- **提示词**：`新车`、`上市`、`预售`、`改款`、`换代`、`全新`
- **⚠️ 只收全新车系，不要改款 / 年款 / 衍生款【高频踩坑点】**：本板块**只收录"全新车系"（车系首次出现）**。改款、年款、加长 / 衍生版（如既有车系的「L 版」「PRO 版」、换代车型）一律不选，除非现象级重磅（极少）。用户明确要求「新车上市只要全新，不要改款，放三个即可，除非重要」。
- **✅ 全新判据（必做，防止误收改款/换代）**：对每条候选车型，去 **汽车之家（autohome）**搜索 `车型名 上市时间`，查该车系是否有历史上市记录——
  - 若车系**此前已有上市记录**（本次为改款 / 年款 / 换代 / 新增配置），则**不算全新车系**，剔除；
  - 只有车系**首次出现、车型库无历史上市时间**的，才是全新车。
  - 示例：比亚迪秦MAX（秦家族新增大杯，2026-08-13 首次上市）= 全新；某车系的「2027 款」或「L 版」= 改款 / 衍生，剔除。
- **标准工作流（三步：pcauto 找候选 → 汽车之家核全新）**：
  1. **找候选**：打开 `https://price.pcauto.com.cn/cars/6/`，筛选符合本周日期（本任务 2026.08.01–08.07）上市/预售的新车。**注意：太平洋汽车这里可能含改款、换代车，一并纳入候选即可**，不要此刻就过滤。
  2. **核全新（关键）**：对每条候选，去**汽车之家**搜索 `车型名 上市时间`，确认该车系是否"全新车系"——只有"车系首次出现、无历史上市时间"的才保留进新车上市；改款/换代（既有车系的年度款、L/PRO 版）剔除。
  3. **补资讯**：对保留的全新车型，用百度搜索 `车型名 上市 2026年8月 价格 配置`，补充发布时间、售价、核心配置、定位。
- **日期**：本任务 2026.08.01–08.07。
- **条数**：3 条左右即可（全新车少则 3 条，除非重要否则不超 5 条），不要为凑数放改款/换代。
- **撰写规则**：每条含「车型 + 上市/预售时间 + 售价区间 + 核心卖点/定位」；**只放全新车系**，摘要新车条也只放全新车系。
- **JSON 去向**：`section="新车上市"`，`subsection=""`。
