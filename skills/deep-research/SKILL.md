# 深度调研（Deep Research）

## 0. 运行边界

- 本 Skill 服务**需要外部公开信源**的调研任务。只依赖内部访谈/问卷/口碑数据即可回答的问题，应交给用户洞察或竞品对标智能体，不走本 Skill。
- 内部销量、成交价等业务数据禁止传入任何联网搜索/精读工具。
- 工具回执与来源清单是证据；模型自述"已完成调研"不是完成证据。
- 禁止编造：没有检索到的信息不得出现在报告中；缺口即发现，明确声明。

## 1. 意图分类与深度分级

| 输入特征 | 意图类型 | 默认深度 | 输出模板 |
|---|---|---|---|
| 两个及以上对象的优劣势比较 | 对比分析 | L2 | references/comparison-analysis.md |
| 单一主题的系统性研究（是什么/为什么/怎么样） | 研究报告 | L2-L3 | references/research-report.md |
| 单一可核验事实（某车型续航、某价格、某日期） | 事实核查 | L1 | 直答（≤3 次检索，不产出报告） |

深度预算：

| 深度 | 范围 | 预算上限 |
|---|---|---|
| L1 | 单一事实核验 | ≤3 次检索 |
| L2 | 标准调研（报告 4-6 章节） | ≤10 次检索、≤24 研究节点 |
| L3 | 深度建模（多维 + 格局分析） | ≤16 次检索、≤32 研究节点 |

## 2. 四段工作流

### 2.1 接收与路由

1. 判断意图类型（对比分析 / 研究报告 / 事实核查）与调研对象。
2. 校准深度（L1-L3），据此设定检索预算与章节规模。
3. 调用 skill_plan_tasks 建立任务图：意图分类 → 检索计划 → 分轮取证 → 交叉校验 → 撰写报告 → 独立验收。

### 2.2 迭代取证循环（核心引擎）

```
子问题分解 → 联网检索 → 精读原文 → 交叉验证 → 缺口修正 →（循环或终止）
```

**工具优先级（严格遵守）：**

1. 搜索：`any_search` → `tavily_search`（依次尝试；同一查询不在两个搜索工具间重复刷屏）
2. 精读：搜索拿到 url 后再 `web_fetch`，不跳过搜索直接精读
3. 公开口碑：`mcp__reputation_data_mcp__*`（车主/网友观点，独立第三源）
4. 子问题相互独立时并行分解取证；每轮显式产出：已验证事实（带 [cite:N]）+ 缺口清单 + 下轮理由

**终止条件**（满足其一）：核心论点 ≥3 个独立来源交叉验证；剩余缺口可忽略并在报告中声明；预算耗尽（必须显式声明，不得静默降级）。

### 2.3 交叉验证与冲突处理

- 来源一致 → 综合陈述并引用。
- 来源冲突 → 并列呈现双方数值/口径与分歧原因（统计口径 / 时间差 / 立场偏差），禁止武断择一。
- 数据不足 → 标记 `[数据不足]`，写入缺口声明；不推测、不脑补。

### 2.4 交付

1. 报告篇幅超过约 4000 字符时分段交付：按序写入 `working/report-parts/`（01- 前缀可排序文件名，每段 ≤3500 字符，最后一段必须是完整参考来源清单），然后调用 `scripts/assemble_report.py` 合并为 `outputs/research-report.md`；短报告可直接一次写入 `outputs/research-report.md`（artifact_kind 填 `research_report`）。
2. 调用 skill_run_script 执行 `scripts/validate_report.py`，args_json 填 `["outputs/research-report.md"]`，按返回 failures 修复后重新合并/登记。
3. 调用 skill_validate_run，required_artifacts_json 填 `["outputs/research-report.md"]`；passed=true 才能宣告完成。
4. 最终回答：给出结论摘要 + 关键发现，注明完整报告路径；不要在回答里复述全文。

## 3. 信源分级与引用纪律

| 层级 | 来源类型 | 用途 |
|---|---|---|
| P0 | 工信部申报公告、官方参数页、企业财报/公告 | 硬参数唯一锚（续航/电池/整备质量等） |
| P1 | 权威媒体、行业白皮书、研究机构 | 市场数据、销量、趋势 |
| P2 | 专业评测社区（带实测数据的） | 定性体验、技术拆解 |
| P3 | 论坛、百科、自媒体 | 仅作线索，不锚定结论 |

引用纪律：

- 正文引用一律用 `[cite:N]`，N 对应报告末尾「参考来源」清单编号；无对应来源的 [cite] 视为虚构。
- 定量结论必须来自 P0/P1；仅 P3 支撑的说法必须标注 `[待核实]`。
- 单一来源不能独立锚定核心结论（标注 `single_source`）。
- 每条来源记录：编号、标题、URL、层级（P0-P3）、信息时点（as_of）。
- 相互转载不算独立来源；官方口径与媒体转述冲突时以官方为准并注明。

## 4. 红线规则

1. 禁止编造数据、来源、URL；检索不到就写缺口。
2. 推断与事实分离：事实带 [cite:N]，判断标注"研究假设/判断"。
3. 不把访谈原话、问卷比例与联网数据混算；三类来源分开标注。
4. 同工具同参数不重复调用；失败后换策略，不循环重试。
5. 完成证据 = 任务图全完成 + 报告产物 + validate_report.py 通过，不是模型自述。
