# 二次开发扩展指南

## 场景一：只更换月份

不改代码。新增当月工作表，保持既有分区、列和单位一致；在问题中指定月份或通过 `sheet_name` 指定工作表。

## 场景二：更换企业模板

1. 复制原业务母版，保留 PowerPoint 原生图表和表格。
2. 确认每页标题、正文、图表和表格对象数量。
3. 在 `profile.yaml` 更新模板路径。
4. 调整渲染器的对象定位规则，避免仅按对象顺序猜测。
5. 用至少两个月份回归，检查数据替换、字体、溢出和重叠。

## 场景三：新增一页品牌竞争格局

推荐操作清单：

1. **业务定义**：在 `page_specs.yaml` 增加 `brand_competition`，说明标题、指标、图表和分析重点。
2. **数据契约**：在 `data_contract.md` 增加品牌、企业、销量、份额、同比、环比、CR5 等字段及口径。
3. **数据解析**：新增 `parse_brand_competition(...)`，不要在正文中临时计算不可审计数字。
4. **母版页面**：增加一页可编辑图表和表格，确定稳定的对象名称或占位符。
5. **渲染 handler**：新增 `update_brand_competition_slide(...)`，并注册到页面渲染表。
6. **写作规则**：增加品牌集中度、主力车型贡献、格局提升/分散的解释方法。
7. **质量门禁**：校验品牌份额、CR5、车型归属和正文数字一致性。
8. **少样本案例**：至少准备两个正式月份的标准页及对应原始数据。
9. **回归测试**：覆盖正常、缺字段、份额异常和模板缺页。

## 场景四：其他同事改成自己的报告

建议复制整个 Profile，而不是修改默认 Profile：

```text
profiles/
├── passenger_vehicle_monthly/
└── colleague_brand_monthly/
```

新 Profile 至少拥有独立的：

- `profile.yaml`
- `page_specs.yaml`
- `quality_rules.yaml`
- `narrative_rules.md`
- `data_contract.md`
- `assets/template.pptx`
- `examples/`

运行时通过 `profile_id` 或宿主配置选择 Profile。正式实现前，应先用 2-3 份“原始数据 + 专家交付页”做差距标注。

## 反馈格式

最有利于迭代的反馈不是“这页不好”，而是每个问题包含：

| 字段 | 示例 |
| --- | --- |
| 页面/对象 | 第2页市场深度分析 |
| 标准截图 | 专家5月报告截图 |
| 当前截图 | 当前生成结果截图 |
| 数据依据 | 5月工作表车型级别与TOP15 |
| 问题类型 | 数据、逻辑、原因、措辞、图表、版式 |
| 期望规则 | 先总判，再解释A0和B级代表车型 |
| 验收标准 | 至少2个车型，原因有时间一致证据，不出现内部术语 |

将反馈转成规则、测试和案例，Skill 才会持续复用，而不是只修某一份 PPT。
