# 级别页的车型支撑（9—11页）

基于业务提供的3—8月六份优秀月报，学习其“级别分化—代表车型变化—经核验的产品/市场解释”方法，不复制历史原因或数字。范文原页通常是21—23页，不能按本产品9—11页直接读取同页码。

## 实际执行

网页后台 `utils/monthly_segment_facts.py` 由本轮已验收数据包本地计算：

- 单月份额用当月级别销量除以当月类别合计；累计份额使用同期累计，不互换。
- 车型销量、同比和环比必须按车型与月份配对，保留比较值和计算结果。
- 扁平DOM缺少空白单元格时，不能把下一车型的同比挪到上一车型，也不能猜新车缺失的同比；不能定位年月的行不进入最小事实包。缺口记录在本地，不用历史报告补数。
- 最小模型包只包含当页级别事实、最多四款单月代表车型及相关累计事实。取证插件/搜索只接收公开实体名称和月份，不接收内部测量值。
- 从完整的级别比较范围计算 `derived_facts`：同比净增减、净减贡献占比、组合份额及份额较上月变化。记录精确事实ID、口径、原始操作数、公式和来源ID；组合份额按原始销量计算，不能相加已四舍五入的份额。缺少完整比较范围时不计算总净减贡献，不把缺失当零。
- 先在本地用当月事实形成 `fact_grounded_draft`，为模型保留正确的级别、月份、车型与数值配对，模型负责加强判断和措辞。草案按实际正负方向动态选择，不能把8月的“收缩/承压”固化给后续月份。

`utils/monthly_report_narrative.py` 在网页任务真实调用中要求三层正文：

1. `core`：最重要的级别分化，选择同比/环比异常而非平铺所有级别。
2. `structure`：必要的单月/累计份额或规模支撑，写明口径。
3. `models`：至少两款与主判断相关的代表车型，逐款写销量及同比或环比，并关联车型级事实ID。优先上升与下降对照，不机械追求排行榜，也不能只列车型名称。

合计目标约三行（125—150显示宽度），可调换三层次序以适应业务表达，但不删掉车型支撑。超预算回到模型凝练，禁止直接截掉末尾、缩小字号或扩大文本框遮住图表。

六份范文的关键是解释“谁支撑、谁拖累、为什么不足以扭转整体”，而非数字列表加“表现分化”：

- 轿车优先比较级别增减量及代表车型是否普遍改善，不把A0泛称包含A00的“小型车回升”。
- SUV可用经核验的两端净增与主流级别净减关系，避免无时序证据的“市场修复”。
- MPV结合主体级别份额与销量方向，选择两款代表车型解释内部压力差异；已有份额迁移时不机械重复累计份额。
- 车型集合不完整时，不把两款代表写成“主流/全部车型均变化”。不猜新车缺失同比；没有可定位单元格时选择其他可核验车型。

## 验收与恢复

- 校验的是最终写入正文的车型信息，不以标题提到车型代替正文支撑。
- 每款车型的数量、增长方向和指标种类须与所引用行匹配；甲车型的数字在页面出现也不能证明乙车型写法正确。
- 标题与正文都检查级别方向、销量和份额，混合单月/累计逐指标识别口径。净增减不是销量，份额变动须有基期，A级和B级、组合级别间不能互借数字。
- 车型名与数量须分开，`别克GL8 5874辆`不能拼接成`GL85874辆`再被错误换算成8.6万辆。该隔离在模型规范化及PPT写入前执行。
- 普通增长不自动证明“主要贡献/拖累”，需要独立贡献量测算；部分车型集合不允许声称榜首。原因仍须按证据等级处理。
- 每个合格页面立即保存 `narrative-Bx-page-N.json`，仅将遗漏或未通过页送入后续重试。模型漏返回一页不应丢弃其他合格页。连续失败保留页面、卡片和取证检查点，不允许失败候选被误存为已通过。
- 模型只接收草案所需的代表车型、单月级别及测算关系；无必要的累计和其他车型留在本地，不让信息菜单稀释主判断。
- 模型连续三次润色仍未通过时，可验收当月本地事实关系草案，但必须通过完全相同的数字、实体、贡献和三行门禁。以 `generation_method=fact_grounded` 明确标记并保留模型失败原因，不能伪称模型润色成功；草案不合格则仍停下等待恢复。合格事实草案不是旧月数据、缺失值补造或一句话简版。
- 新任务可复用同月完整卡片，但不沿用历史主旨句。规则或事实包变化时，只使相关主旨句批次和概述失效，不重采45张卡片。
- 点击“生成PPT版”必须携带原run_id，只读取本轮验收数据与证据包并发布下载。
