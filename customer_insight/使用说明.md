# 用户洞察 · 使用说明书

浏览器打开 `http://127.0.0.1:7860/#insight` 进入「用户洞察」。

这页不是四个彼此独立的功能，而是**一条从“用户说了什么”到“结论靠不靠谱”的分析链路**。先想清楚你要回答哪类问题，再选对应 Tab。

---

## 一、先看数据底账

| 数据 | 规模 | 能回答 | 不能回答 |
|---|---|---|---|
| 定性深访 | 63 位受访者 | 用户原话、动机、选购/弃购理由、使用场景 | 不能算比例、不能代表全市场 |
| 定量问卷 | 1380 份 | 选项分布、占比、群体差异、满意度打分 | 不能解释“为什么” |

两条数据独立，**不要把访谈里的“很多人说”写成百分比，也不要把问卷比例说成用户原话**。

---

## 二、四个 Tab 是什么关系

四个 Tab 对应四个递进的问题，不是四套重复功能：

| 顺序 | Tab | 回答的问题 | 主要输出 | 数据来源 |
|---|---|---|---|---|
| 1 | 检索问答 | 用户**到底说了什么**？ | 带 `[E#]` 引用的结论 + 原话证据卡 | 63 位深访 |
| 2 | 定量统计 | **有多少人**这么想？ | 题目选项的计数与占比 | 1380 份问卷 |
| 3 | 专题洞察 | 结论**是什么**？ | 战胜战败、圈层、痛点、再购、需求矩阵 | 深访 + 问卷 |
| 4 | 对比与验证 | 结论**靠不靠谱**？ | 联合建议、竞品对比、定性定量互证 | 两套数据合并 |

页面顶部也写了这条路径：**找原话 → 看比例 → 得结论 → 交叉核对**。

### 我要做什么，该去哪个 Tab

| 你的诉求 | 去这里 |
|---|---|
| 找几句可以直接引用的用户原话 | 1 检索问答 |
| 验证“后排空间很重要”到底覆盖多少人 | 2 定量统计 |
| 解释某车型为什么卖得好/卖不动 | 3 专题洞察 → 战胜战败分析 |
| 看用户分成哪几类人 | 3 专题洞察 → 圈层画像 |
| 找产品最该改进的短板 | 3 专题洞察 → 满意度痛点 / 需求×配置矩阵 |
| 判断用户下一辆车还买不买我们 | 3 专题洞察 → 再购意愿与品牌忠诚 |
| 要一段能直接汇报的综合结论 | 4 对比与验证 → 联合洞察 |
| 看我们和竞品差在哪个维度 | 4 对比与验证 → 竞品横向对比 |
| 核对原话和统计是否一致 | 4 对比与验证 → 圈层交叉验证 |

## 三、功能逐个用法

### Tab 1｜访谈证据检索

**用途**：把一个业务问题变成可引用的访谈证据，回答“用户原话怎么说”。

**操作**

1. 在输入框写一个具体问题，点「检索证据」。
2. 等待返回结论和证据卡。

**输入示例**

- `哪些用户提到后排空间和孩子？`
- `用户为什么选择增程而不是纯电？`
- `计划换车的用户是怎么考虑换车时机的？`
- `试驾后放弃唐L的用户说了什么？`

**怎么读结果**

- 结论中的 `[E1]`、`[E2]` 是**本次查询的临时证据序号**，翻到下方证据卡即可对应。
- `R035` 是**受访者匿名编号**，不是排名，也不是用户 ID。
- 证据卡包含：城市 · 车型 · 题号 · 原话 · 时间戳 · 说话人 · 置信度。
- 同一道题会优先展示受访者的**回答内容**，而不是访谈员提问。

**注意**

- 问题越具体越好。问“用户怎么看车”太宽，问“有孩家庭怎么看后排”更容易命中。
- 没有足够证据时系统会返回「现有访谈证据不足以支持该结论」，这是防止编造，不是故障。
- 单次最多返回 8 条证据；同一受访者最多 3 条，避免一个人刷屏。

---

### Tab 2｜问卷分布统计

**用途**：看某个问卷题目在不同人群中的选项分布和占比。

**操作**

1. 第一个下拉选「切分维度」（按什么人群拆）。
2. 第二个下拉选「问卷题目」。
3. 点「统计分布」。

**怎么读结果**

- 每个分组显示选项、计数和占比。
- 占比只在这 1380 份问卷内有效，不是全市场渗透率。

**注意**

- 想验证访谈里的说法，先来这里看比例，再回 Tab 1 找原话解释原因。
- 题目和维度都是下拉选择，不需要手输。

---

### Tab 3｜专题洞察

这个 Tab 下有 5 张卡片，按“为什么买/不买 → 谁在买 → 哪里不满意 → 还会不会买 → 该改什么”的顺序使用。

#### 3.1 战胜战败分析

**用途**：解释某车型为什么被选中、为什么被放弃。

**操作**：输入目标车型 → 点「分析战胜战败」。

**输入示例**：`唐L`、`理想i8`、`零跑C16`、`深蓝S07`

**输出**

- 目标车型的购买者人数与匿名编号。
- 按原因类别分组的标签：对比过谁、最终放弃谁、选购原因、能源形式取舍。
- 相关访谈证据卡。

**注意**：车型名要与库内名称一致，先试短名称；查不到时换一个车型名再试。

#### 3.2 圈层画像

**用途**：不输入任何条件，先看清用户由哪几类人构成。

**操作**：点「查看圈层画像」。

**输出**：按购车类型划分的圈层，每个圈层给出样本量、价格段、年龄段、性别、热门车型。

**注意**：样本量过小的圈层会被过滤，避免用十几个人下结论。

#### 3.3 满意度痛点

**用途**：找出某群体最不满意的产品维度。

**操作**：选群体维度 → 输入该维度的**准确取值** → 点「满意度痛点」。

**输出**：16 个产品维度的低分率（≤6 分）、均分、低分人数/样本数，按低分率从高到低排序。

**输入示例**

- 维度选「车型」，输入 `唐L`
- 维度选「价格段」，输入 `10-15万`
- 维度选「年龄段」，输入 `36-40岁`
- 维度选「城市」，输入 `沈阳`

**注意**：这是**精确匹配**。输入 `首购` 查不到数据，必须输入完整取值（见文末速查表）。

#### 3.4 再购意愿与品牌忠诚

**用途**：判断某群体下一辆车什么时候换、换什么技术、还买不买同品牌。

**操作**：选群体维度 → 输入准确取值 → 点「再购意愿」。

**输出**：再购时间、再购技术类型、再购意向品牌、是否同品牌四组分布。

**注意**：同样要求精确取值；“同品牌”只反映样本意愿，不等于真实复购率。

#### 3.5 需求×配置矩阵

**用途**：把“用户很在意”和“用户不满意”放在同一张图里，找优先改进项。

**操作**：选群体维度 → 输入准确取值 → 点「需求×配置矩阵」。

**输出**：16 个维度按“购车关注度 × 使用满意度”落入四象限。

**怎么用**

- **高关注 + 低满意**：优先改进，直接影响购买决策。
- **高关注 + 高满意**：继续保持，可作为传播卖点。
- **低关注 + 低满意**：暂不优先投入。
- **低关注 + 高满意**：可评估是否需要继续堆配置。

---

### Tab 4｜对比与验证

#### 4.1 联合洞察

**用途**：把定性原话、战胜战败和定量统计合成一份可汇报的配置建议。

**操作**：选颗粒度（目标车型 / 购车类型 / 用户圈层）→ 输入对象 → 点「联合洞察」。

**输入示例**

- 颗粒度「目标车型」，输入 `唐L`
- 颗粒度「购车类型」，输入完整购车类型文本
- 颗粒度「用户圈层（年龄段）」，输入 `36-40岁`

**输出**：三源摘要 + 配置优先级建议。

**注意**：适合汇报，不适合替代原始证据；引用时仍要回看具体证据卡。

#### 4.2 竞品横向对比

**用途**：横向看各车型在 16 个维度上的差异。

**操作**：选对比口径（购车关注度 / 满意度低分率）→ 点「竞品横向对比」。

**输出**：车型 × 维度的对比表，并标出差异最大的维度。

**注意**：不需要输入车型，系统按现有车型汇总；关注度是“勾选比例”，低分率是“≤6 分占比”，两者不要混着解释。

#### 4.3 圈层交叉验证

**用途**：把某圈层的定性原声和定量指标并排，检查“听到的”和“统计的”是否一致。

**操作**：选群体维度 → 输入准确取值 → 点「圈层交叉验证」。

**输出**：左侧定性证据，右侧定量指标。

**注意**：如果两边结论冲突，优先检查样本量和取值是否填对，不要直接取对自己有利的一边。

## 四、三条推荐分析路径

### 路径 A：诊断一个车型

1. Tab 3 → 战胜战败分析：看买它的人和放弃它的人分别怎么说。
2. Tab 3 → 满意度痛点：输入该车型，找最疼的 3 个维度。
3. Tab 3 → 需求×配置矩阵：确认哪些是“高关注低满意”。
4. Tab 1 → 检索证据：找对应原话，形成汇报素材。
5. Tab 4 → 联合洞察：生成综合建议。

### 路径 B：诊断一类人群

1. Tab 3 → 圈层画像：确认这类人的规模和特征。
2. Tab 2 → 定量统计：看关键题目的比例。
3. Tab 3 → 再购意愿：判断未来流向。
4. Tab 4 → 圈层交叉验证：核对原话与比例。

### 路径 C：验证一个观点

1. Tab 1 → 检索证据：先找支持与反对的原话。
2. Tab 2 → 定量统计：看这个观点覆盖多少人。
3. Tab 4 → 圈层交叉验证：确认是否只在某一人群成立。

## 五、群体取值速查表（精确匹配）

「满意度痛点」「再购意愿」「需求×配置矩阵」「圈层交叉验证」「联合洞察」都使用精确匹配，请照抄下列取值。

**购车类型（必须整段照抄）**

**城市**：`上海`、`南京`、`合肥`、`天津`、`太原`、`宁波`、`广州`、`成都`、`杭州`、`武汉`、`沈阳`、`深圳`、`西安`、`郑州`、`重庆`、`长沙`、`青岛`

## 六、常见问题

**1. 为什么输入“首购”查不到数据？**
这些功能按完整文本精确匹配，`首购` 不是库内取值，请照抄速查表中的整段文本。目前页面还没有下拉选择，这是已知限制。

**2. 为什么检索问答说“证据不足”？**
系统只允许引用检索到的证据，证据不够就拒答。可以换更具体的问法，或改用“主题 + 人群 + 场景”的描述。

**3. E1 和 R018 是什么？**
`E1` 是本次结果的证据序号，只在本页有效；`R018` 是受访者匿名编号，用于回源和区分不同人。

**4. 为什么访谈只有 63 人，能不能说“大多数用户”？**
不能。63 人是定性样本，只能说明“有人这样想、为什么这样想”；要说比例，请用 1380 份问卷的定量统计。

**5. 为什么两个功能的数字对不上？**
深访和问卷是两套独立样本，题目口径也不同。对不上时先确认样本范围，不要强行合并。

**6. 页面改了但没生效？**
`home.html` 在服务启动时读入内存，改版后需要重启 7860 服务；`assets/` 下的 JS/CSS 刷新浏览器即可。

## 七、使用边界

- 结论是**样本洞察**，不是全市场统计。
- 所有受访者只显示匿名编号，不显示姓名。
- 系统不会编造原话；没有证据时会明确拒答。
- 定量占比只在问卷样本内有效，不能外推为市场占有率。
- 关键决策建议同时查看“原话 + 比例 + 样本量”，不要只看单一结论。
