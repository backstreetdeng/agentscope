# 款型名称维护

正式库 `public.new_car_model` 新增可空字段 `style_name TEXT`，汽车之家款型 ID `model_style_id` 仍是唯一主键。名称是款型本身的属性，不另建映射表。已有 14 个基础字段不修改，新增字段不会改变款型 ID、上市时间或历史编号。

## 本次来源

用户提供的 2026年W1-W40（20260101-20261003）新车上市数据汇总-20261009.xlsx，`数据表` A列汽车之家款型ID、U列汽车之家款型名称。按精确 ID 对应，不按车型名称猜测。

## 每周步骤

1. 完成基础款型增量发布。基础导入必须列出写入字段，不用删除重建或整表替换；旧12列基线导入不清空已维护的名称。
2. 在维护端使用 `ops/extract_new_car_style_names.py --workbook <Excel路径> --output <本次映射JSON路径>` 提取 A/U。使用配置好的 Python/openpyxl 读取；不修改 Excel。头部必须匹配，ID 必须为正整数；空名称、无效 ID、同 ID 不同名称进入对账，不能猜测。
3. 使用 `ops/publish_new_car_style_names.py --mapping <映射路径>` 只读对账。
4. 核对匹配数、缺失 ID、源表独有 ID 和名称冲突。源表独有 ID 不会自动新增基础款型；已有不同名称不会覆盖，需业务确认。
5. 核对后加 `--apply` 发布。程序备份原表、短事务填补空名称，校验其他字段完全保留及 MCP 读取权限。重复运行相同输入更新 0 条。
6. 从正式新车 MCP 校验名称。网页一览、按款型检索、详情标题读取同一个字段，不使用本地映射JSON作为展示来源。

## 注意

这次在146正式库增加了一个字段，需让维护端知悉；未改政策或口碑表结构。脚本 `.env.new-car` 连接信息必须在维护电脑私下配置，不写入交付文档。数据库账号需要对应表的 SELECT/UPDATE；首次迁移才需要表所有者的 ALTER 权限。展示端 MCP 继续只读。

本次备份在 `outputs/new-car-style-names/20261013T084728/before-database.json`，对账在同目录。恢复前核对后来是否已有其他维护更新，不能覆盖后来批次；回退名称应按 ID 并校验当前值后恢复备份，而不是删除整表或去掉新增列。
