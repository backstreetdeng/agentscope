# 第一部分：系统灵魂（先读这个，再看代码）

## 1.1 一句话总纲

**在中国做市场预测，赢在"信息与结构"，不赢在"模型"。**

本项目所有公开研究交叉验证：精度最高的方案没有一个是赢在模型结构——中国 XGBoost 研究（MAPE 6.09%）赢在政策哑变量+基建复合因子；AOA-TFT 论文赢在百度搜索指数+舆情；真正的机构（S&P、Deloitte）赢在 TCO 结构模型+专家校验。**我们自己也验证了**：Chronos-Bolt 零样本在急速下滑的燃油序列上全场最优（5.98%），但从零训练的 LightGBM 在总量上不敌季节naive——没有单一模型全面领先，**多样性+对账比调参更重要**。

## 1.2 十二条不可压缩的洞见（设计决策的依据）

| # | 洞见 | 在本系统中的落点 |
|---|---|---|
| 1 | **误差结构决定方法结构**：2027年误差80%来自事件（政策），20%来自时序噪声 | 先解剖误差再选模型；L2事件层优先级高于模型层 |
| 2 | **单点数字是伪精度**：机构对2027分歧达±15%，分歧本身就是信息 | 一切输出为 P10/P50/P90 + 三情景；从不交付单点 |
| 3 | **精度是分层设计出来的**：全国3-8%，小省×动力20-35%是物理规律 | 精度路由：重注总量层；小颗粒用份额法传导精度，不独立预测 |
| 4 | **恒等式=免费精度**：分省加总=全国、动力份额和=100%是先验信息 | 入库强校验 + middle-out 对账，双重保证 |
| 5 | **特征工程收益 >> 模型复杂度** | 重投事件库+领先指标，模型只用成熟组件 |
| 6 | **与其预测更远，不如看得更早**：信息链 搜索→订单→上险→零售→批发 | nowcasting 层（车企交付公告领先乘联会2周）比磨模型性价比高 |
| 7 | **中国市场是"政策时钟"不是趋势线**：末班车效应（2025-12冲133.7万辆→2026Q1 -21%）+8年换购周期 | 事件库是系统心脏；预测的日历驱动 |
| 8 | **渗透率的分子分母陷阱**：渗透率上涨一半来自燃油衰退（分母缩水） | 分子分母分别预测，绝不直接外推渗透率 |
| 9 | **口径即世界观**：零售/批发/上险选错，模型再准也是精准地错 | metric_dict 口径字典锁死；point-in-time 禁止回填 |
| 10 | **锚定-修正-对账**：定量基线锚死，事件机械修正，禁止"综合考虑"式黑箱 | L1→L3→L2 流水线；AuditForecast 范式 |
| 11 | **模型分工**：基础模型管"像"（形态迁移），结构模型管"理"（因果），Agent管"信"（新信息采集） | M3 Chronos / S曲线 / 采集Agent 三者互补不互代 |
| 12 | **复利来自错误的分层归因**：错不可怕，不知道错在哪层才可怕 | forecast_runs 档案 + 每月回测记分卡 |

## 1.3 不是为了预测而预测：预测的唯一存在理由是支撑决策

**这是集成到战略决策智能体时最重要的一节。** 预测引擎不产出"数字"，它产出"决策差异"：

| 预测输出 | 服务的决策 | 触发条件设计 |
|---|---|---|
| 总量区间 + 动力结构 | 生产排产/产能规划 | P10低于产能基准线→预警排产风险 |
| NEV渗透率(分子分母拆开) | 产品线投资节奏、燃油退坡时间表 | 渗透率路径穿越规划线→触发战略复盘 |
| 分省×动力结构 | 渠道压库、区域营销资源分配 | 省级偏差连续2月>阈值→区域预警 |
| 情景差值(乐观-悲观) | 风险敞口对冲、预算弹性设计 | 区间宽度骤增→不确定性预警 |
| 事件修正链 | 政策应对预案 | 政策公告→30分钟内重算情景 |
| 命中率记分卡 | 预测体系自身的投资决策 | MAPE连续恶化→模型复盘 |

**集成铁律：智能体的每一个回答，都必须能回答"这改变了什么决策"。** 讲不出决策含义的预测，一律不出手。

# 第二部分：系统架构（已实现部分）

## 2.1 分层架构

- **交互层**：4个Agent工具 + FastAPI（/indicators /forecast /scenario /explain）
- **编排层**：LLM只做意图识别/编排/解释（防幻觉硬边界：LLM永不直接产数值）
- **预测层**：
  - L1 定量锚定：M1季节naive / M2 LightGBM分位数 / M3 Chronos-Bolt(零样本)，可选等权集成（USE_M3_ENSEMBLE）
  - L3 对账校准：middle-out 分量缩放至总量P50 + conformal带宽校准
  - L2 事件修正：events.csv 三情景系数机械乘法，total=Σ分量（恒等式）
- **分省层**：份额法（省份额×全国预测，精度路由，分省加总恒等于全国）
- **数据层**：SQLite四表 indicators / events / metric_dict / forecast_runs
- **采集层**：目前手工CSV入库；定时采集Agent为路线图项

## 2.2 目录结构与文件职责

- README.md —— 运行指南+验收结果+已知问题（先读）
- MIGRATION.md —— 本文档
- requirements.txt —— 依赖清单
- db/schema.sql —— 四表结构（forecast_runs主键=(run_id,ym,powertrain)，防止档案互相覆盖）
- db/market.db —— SQLite库（当前含占位数据，可删库重建）
- data/make_sample_data.py —— 全国模拟数据生成器（结构真实：季节/春节/政策冲击）
- data/make_province_sample.py —— 分省模拟数据生成器（31省，恒等式归一）
- data/retail_monthly.csv —— ★ 替换目标：乘联会真实数据（列:ym,total,bev,phev,hev,ice）
- data/province_monthly.csv —— ★ 替换目标：分省数据（列:ym,province,bev,phev,hev,ice）
- data/events.csv —— ★ 事件库（需分析师评审三情景系数+补证据链）
- data/cpca_real_anchors.csv —— 已采集的真实锚点（含来源，供校验）
- ingest/ingest.py —— 全国入库：恒等式校验+口径字典+point-in-time
- ingest/ingest_province.py —— 分省入库：分省加总=全国校验
- features/build_features.py —— 特征工厂：lag1/2/3/6/12、rolling、月历、春节、农历月维护表
- models/m1_baseline.py —— 季节naive+漂移（不可跳过的基线）
- models/m2_lgbm_quantile.py —— LightGBM分位数P10/50/90 + conformal带宽校准
- models/m3_chronos.py —— Chronos基础模型（自动降级链chronos-2→bolt-base，离线优先）
- reconcile/reconcile.py —— middle-out对账（份额和=100%）
- events/adjust.py —— L2事件修正引擎（机械聚合，修正链可审计）
- province/share_method.py —— 份额法核心（滚动12月均值×阻尼趋势）
- eval/backtest.py —— 全国四路回测（M1/M2/M3/集成×5序列）
- eval/backtest_province.py —— 分省份额法回测（分层报告）
- run_forecast.py —— 端到端入口：L1→L3→L2→档案落库→三情景CSV
- run_province.py —— 分省下钻入口（读全国预测CSV，恒等式校验）
- agent/tools.py —— ★ 暴露给智能体的4个工具（function calling直接接）
- api/main.py —— FastAPI封装（可选）

## 2.3 数据模型纪律（迁移后必须保持）

1. **point-in-time**：indicators 只插入不更新，修订值新开 series_id/版本；
2. **口径字典**：metric_dict 中每个术语唯一指向（"NEV渗透率"=retail.(bev+phev)/retail.total，PHEV含增程）；
3. **预测档案**：forecast_runs 每次预测存完整快照（模型版本/数据截止/修正链JSON）——命中记分卡的唯一数据来源；
4. **事件库**：mult_base/bull/bear 为乘法系数，作用于动力分量后 total=Σ分量（恒等式不可破）。

# 第三部分：评测结果与协议（迁移验收基准）

## 3.1 全国层回测（12 origins × h=1..6，模拟占位数据）

| 序列 | M1季节naive | M2 LightGBM | M3 Chronos-Bolt | M2+M3集成 |
|---|---|---|---|---|
| total | 5.07% | 6.65% | 7.21% | 6.75% |
| bev | 5.10% | 6.84% | 9.83% | 7.73% |
| phev | 8.80% | 7.71% | 9.77% | **6.61%** |
| hev | 10.99% | 10.16% | 10.35% | 10.08% |
| ice | 15.03% | 11.16% | **5.98%** | 8.27% |
| P10-P90覆盖(total) | — | 86.1% | 81.9% | 90.3% |

**解读**：M3零样本在急速下滑的ice上全场最优（形态迁移能力）；集成在phev最优；无单一模型全面领先→维持多样性，集成权重等真实数据回测后再定。

## 3.2 分省层回测（份额法，最近6月，h=1）

| 层级 | 份额法MAPE | 省级naive直接预测 |
|---|---|---|
| 大省(≥5%) | 3.61% | 6.12% |
| 中部(2-5%) | 3.49% | 7.14% |
| 小省(<2%) | **3.67%** | 8.00% |

**解读**：份额法把总量层精度传导到每个省，小省不再崩——"精度路由"命题验证成立。

## 3.3 迁移验收四条命令（数字应与旧机一致）

- `python eval/backtest.py` —— 总量M2 MAPE 应≈6.65%（同数据同种子）
- `python eval/backtest_province.py` —— 全省平均应≈3.58%
- `python run_forecast.py` —— base情景2027总量P50应≈2056万辆
- `python agent/tools.py demo` —— 4工具全通过（含情景滑杆delta≈+38万辆）

## 3.4 真实数据上的验收标准（换数据后执行）

- 总量月度 MAPE ≤10%，区间覆盖 80%±10；
- 每个数字可追溯三件事：数据截止日/模型版本/事件修正链；
- 每月5日自动回测 → 命中率记分卡（复利来源）。

## 5.3 Chronos 模型权重（新机需联网一次）

- 设置 `$env:HF_ENDPOINT='https://hf-mirror.com'` 并清除 HF_HUB_OFFLINE；
- 运行：`python -c "from chronos import BaseChronosPipeline; BaseChronosPipeline.from_pretrained('amazon/chronos-bolt-base')"`；
- 下载成功后默认离线推理（m3_chronos.py 自动设 HF_HUB_OFFLINE=1）。

# 第六部分：整合进「乘用车市场战略决策AI智能体」

## 6.1 定位：预测引擎是智能体的"外挂数学脑"

- 战略决策智能体（LLM编排层）下挂四个模块：
  - 数据采集Agent → 喂 indicators/events
  - **预测引擎（本系统）→ 4个工具，产出区间+情景+修正链**
  - 竞争情报/舆情模块 → 与预测交叉解释
  - 报告生成模块 ← 消费预测输出
- **硬边界：LLM从不直接生成预测数值，只调用本引擎并解释其输出。**

## 6.2 四个工具契约（function calling 直接注册）

**配套交付**：`agent/SYSTEM_PROMPT.md` —— 智能体系统提示词模板（含角色硬边界、
回答格式纪律、决策含义话术、可直接注册的 JSON Schema、合格/不合格回答黄金样本）。
整合时直接粘贴该文件，无需自行设计编排规则。

| 工具 | 入参 | 返回 | 智能体话术要点 |
|---|---|---|---|
| query_indicator | powertrain, start, end | 序列值+来源+采集时间 | 必须带来源与口径 |
| run_forecast | scenario(base/bull/bear) | 2027 P10/50/90+渗透率+修正条数 | 先给区间再给P50，说明情景假设 |
| adjust_scenario | event_id, mult | 修改事件系数→重算→delta | "末班车效应调到1.10，总量+38万辆" |
| explain_forecast | ym, powertrain, scenario | 模型版本/数据截止/修正链 | 下钻回答"为什么是这个数" |

**调用纪律（写进智能体系统提示词）**：

1. 任何预测回答必须附：区间、情景名、数据截止日；
2. 用户挑战数字时调 explain_forecast，禁止LLM自行辩解；
3. 涉及"如果…会怎样"一律走 adjust_scenario 重算，禁止心算外推；
4. 回答结尾必须落到1.3节的决策含义表。

## 6.3 月度运营节奏

1. 每月1-3日：采集Agent抓乘联会月报→ingest入库（校验恒等式）；
2. 每月5日：自动回测→命中率记分卡→偏差归因（模型层/事件层/数据层分账）；
3. 每月5-7日：重跑 run_forecast + run_province → 三情景区间更新；
4. 每月10日前：智能体生成《市场行情预测月报》（区间图+情景表+修正链附录+决策触发提示）；
5. 随时：政策公告→adjust_scenario即时重算→预警推送。

## 6.4 与战略系统的数据回流

预测档案（forecast_runs）回灌战略系统两个用途：

1. **命中率记分卡**=决策支持的信任度仪表盘（哪个层级可信、哪个事件假设系统性偏差）；
2. **修正链历史**=政策效果研究的实证素材（"末班车效应上轮+6%，这轮实际+4.8%"）。

4. **永远不要**为了让回测好看而调带宽/调参——精度只能来自数据和结构，校准参数只能在回测协议内定；
5. 记住1.1：如果有一天你在纠结"用什么模型"，先问自己"误差从哪来、哪个决策要吃这个数"。
