## 一、背景与目标

### 1.1 业务背景

市场板块新增【竞品对标】能力：针对上市新车与发布会竞对态势，自主识别目标车型并建立多维竞品池；直连款型配置信息库，融合专业知识库与联网动态，交付精准对标矩阵与战略 So What。

### 1.2 方法论依据与实测证据

- 方法论源：trae-remote-official:deep-research-assistant 插件（研究指挥官四段工作流：接收路由 / 迭代取证循环 / 冲突处理 / 交付路由，及信源分级 P0–P3、≥3 独立来源交叉验证、标注纪律）。
- 实测验证：2026-11-02 以"2026Q3 以来 10–20 万元新能源 SUV 竞品动态"为题完成 L2 全流程实测——10 次检索、2 轮取证、35 源引用、价格阶梯冲突解决（战舰 700 四级价格）、口径分歧保留（Model Y 双口径）、缺口显式声明（比亚迪 Q3）。证据存档 `temp/20261102-deep-research-eval/`。
- 架构结论（实测推导）：方法论为**语义层**（skill 包，移植自插件 3 个 md）；执行为**机制层**（ResearchDAG 泛化为研究执行底座：任务图 / 回执 / 去重 / 波次 / 断点 / 账本）；数据为**三底座**。研究循环的"图"是运行时长出来的，不能预编为静态 workflow，也不能只靠提示词驾驶。

### 1.3 与现有能力的边界

- 不改动：市场预测（保持原状）、Chronos-2、月报、周报既有链路及其测试基线。
- 独立新增：竞品对标为市场板块新能力，不与预测任务耦合。
- 数据红线：内部销量等业务数据禁止传入任何联网搜索/精读工具（沿用现有规则）。

## 二、业务场景与功能需求

### 2.1 核心场景

| 场景 | 输入 | 输出 |
|---|---|---|
| S1 新车上市对标 | 目标新车型（用户指定或公告批次发现） | 竞品池 + 对标矩阵 + So What |
| S2 发布会竞对态势 | 发布会事件 / 竞对动作 | 竞对动态对比 + So What |
| S3 公告批次巡检 | 工信部新批次申报清单 | 新车型清单 + 竞品预警 + 竞品池更新建议 |

### 2.2 功能需求（FR）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR1 | 目标车型自主识别 | 基于三源证据识别竞品关系（配置参数相似度、价格带、车型级别、能源形式、定位），支持人工确认与修正 |
| FR2 | 多维竞品池构建 | 维度：价格带 / 车型级别 / 能源形式 / 智驾配置 / 供给缺口；每维度附证据与置信度 |
| FR3 | 三源取证 | P0 款型配置信息（纯电续航、整备质量、能耗、电池能量等结构化硬数据）；P2 知识库（Phase 2）；P1/P2 联网实时（上市权益、变动售价、交付周期、OTA） |
| FR4 | 交叉校验（核心） | 字段级规则：硬参数以 P0 配置值为唯一锚；价格阶梯化（指导价/先享价/限时价/经销商价分列不合并）；冲突三型分治（口径/时效/立场）；矩阵单元格级标注（来源等级 + 时间戳） |
| FR5 | 对标矩阵交付 | 每格可溯源；缺失标 N/A，禁止编造；支持版本对比（竞品池变更前后） |
| FR6 | 战略 So What | 机会/威胁判断 + 置信度标注；推断与事实显式分离 |
| FR7 | 缺口声明 | `[INSUFFICIENT DATA]` / `[SINGLE-SOURCE]` / `[DISPUTED]` 显式标注；缺口即发现 |
| FR8 | 前端入口 | 左侧导航栏新增顶级入口【竞品对标】（与【市场分析】【市场预测】同级）；页面入 `pages/` 并接路由 + `app.py` 增量 API；不动现有入口与导航项 |

### 2.3 非功能需求（NFR）

| 编号 | 需求 |
|---|---|
| NFR1 可审计 | 每个值可溯源至工具回执；账本可独立校验 |
| NFR2 可恢复 | run_id + 检查点；服务重启后可续跑（对齐 skill-integration-standard 隔离运行要求） |
| NFR3 预算护栏 | 轮次 / 节点数 / 时限 / 搜索配额 / token 预算，超限熔断降级 |
| NFR4 数据安全 | 内部数据不出域；外发查询仅含公开信息 |
| NFR5 模型路由 | 按 L1–L3 深度分级选择模型（flash / pro），遵循 `utils/model_routing.py`，禁止回退未授权提供方 |
| NFR6 回归保护 | **月报红线（2026-11-02 复审后扩展）**：①月报文件 git 零改动；②`benchmark_research_dag` 禁止 import 月报模块；③共享依赖（`custom_tools.py` 等）行为零改动，确需改动须先补最小月报冒烟。周报 / 预测既有测试作为合并门禁 |

## 三、总体架构（三层）

1. **方法论层（skill 包）**：`SKILL.md`（竞品对标路由、证据标准、冲突分型）+ `references/`（对标矩阵与 So What 模板、验收规则）。移植自插件 3 个 md 并按本域改造，运行时按子场景选择性加载，负担有界。
2. **执行层（引擎）**：复制 `utils/monthly_research_dag.py` 的机制为 `utils/benchmark_research_dag.py`，独立演进（2026-11-02 用户决策：复制而非抽取，月报链路零改动）。机制同源：任务图与依赖、回执 + SHA256、签名去重、波次并行、断点恢复、账本校验。规划器模型提议动作，调度器执行并管状态——"模型只提问与解读，工具回执才是证据"。
3. **数据层（三底座）**：款型配置信息（P0，注册为只读工具，用户侧已具备采集能力）；汽车情报知识库（P2，Phase 2 常驻爬虫日更聚合）；联网实时（P1/P2，复用现有 SearXNG/Exa/Tavily 三级搜索 + 双精读工具）。

四段工作流分工：①接收路由、④交付路由几乎全进代码；②迭代取证、③冲突处理骨架进代码、判断进语义层。

## 五、技术难点与规避（重点）

| # | 难点 | 风险 | 规避方案 |
|---|---|---|---|
| 1 | 研究引擎复用 vs 月报稳定性 | 改坏月报既有链路 | **2026-11-02 用户决策：复制而非抽取**——`monthly_research_dag.py` 完全不动，复制机制为 `utils/benchmark_research_dag.py` 独立演进（文件头标注溯源）。月报路径零改动、无回归面。已知代价：机制双份维护；缓解：溯源标注 + 出现第三个研究场景时再抽取公共 core（rule of three） |
| 2 | 款型配置数据契约 | 硬参数藏在 key-value 长表、无批次字段 | 实际结构已确认（2026-11-02）：纯电续航/整备质量/能耗/电池能量按 `pz_name` 映射提取；S4 建 pz_name → 标准字段映射表并做对账（款型数 ↔ 明细数 ↔ car_id 一致性）；P0 锚定以 car_id + create_time |
| 3 | 模型与搜索成本失控 | token / 付费搜索 API 消耗爆炸 | L1–L3 深度分级路由；引擎侧预算护栏（节点数/轮次/时限/配额熔断）；实测基线：L2 任务 10 次检索 |
| 4 | ReAct 迭代上限 | 单 agent `max_iters` 不够或循环失控 | 取证循环放引擎波次制（参考 `execute_pending` 并行就绪节点模式），不依赖单 agent 迭代上限 |
| 5 | 搜索配额与降级 | 付费 API 配额耗尽、结果质量波动 | 沿用三级降级链（SearXNG → Exa → Tavily）+ 配额计量与熔断；同工具同参签名去重（引擎已有） |
| 6 | 知识库工程量 | 反爬、合规、去重、存储检索质量 | 分期规避：Phase 1 顶替方案先跑通；Phase 2 礼貌抓取（频控 / robots 尊重）、增量去重、源清单先窄后宽 |
| 7 | 交叉校验规则工程化 | 规则与数据 schema 脱节、口径漂移 | 字段级规则库与申报 schema 同源维护；每条规则可单测（如"续航以申报值为锚"） |
| 8 | 上下文窗口压力 | 工具回执淹没模型上下文 | 回执预览限长（沿用 `observations` 的 preview_limit 模式）+ 结构化摘要进上下文 |
| 9 | 验收标准失守 | "接入中"冒充"已接入" | 对标矩阵独立验收器（硬参数与申报 100% 一致、每格带源、冲突显式、缺口如实）+ skill-integration-standard 12 项清单；代表性真实任务通过才算接入 |
| 10 | 前后端集成 | 破坏现有页面与 API | 新页面入 `pages/` 接路由；`app.py` 只增不改；交付前跑 `workspace_hygiene.py` 与既有页面测试 |

## 六、验收标准

1. **业务验收**：用户对 1 个真实新车型（建议试点：10–20 万新能源 SUV）的对标矩阵与 So What 签收。
2. **工程验收**：skill-integration-standard 12 项清单全部满足（Registry 包校验 / 隔离运行 / 任务图与检查点 / 重启恢复 / 独立验收发现故意错误 / 修复循环 / 回放下载 / 能力对等 / 场景测试覆盖）。
3. **矩阵验收器**：硬参数与款型配置信息一致率 100%；每格带来源等级与时间戳；价格阶梯分列；冲突双边呈现；缺口如实声明。
4. **回归**：周报 / 预测既有测试通过；月报按 NFR6 红线核查（git 零改动 + import 禁令 + 共享依赖行为核查）。

### 9.2 合规边界

1. 仅抓取公开网页内容，尊重 robots.txt；不抓登录后内容，不绕过反爬机制（不破解验证码/签名）。
2. 频控与礼貌抓取：标识 User-Agent、限速、避开高峰。
3. 版权内容只存摘要 + 链接 + 元数据，用于检索与证据引用，不全文转载分发。
4. 汽车之家 / 懂车帝口碑不再爬取（法律声明对互动内容有明确保护，且数据已有）。
5. 微信公众号内容（电动公社等）不直接爬取；确需时经人工订阅或白名单渠道导入。
