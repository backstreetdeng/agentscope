## 一、第二阶段要达到什么

在现有新版预测页面的基础上，增加 **SARIMAX 季节性统计预测和变量关系分析**，与 Chronos-2 和简单季节性基线公平比较，帮助判断不同地区、动力类型和预测周期适合使用什么方法。

第二阶段不覆盖既有 Chronos-2，也不改变原市场预测功能。先做**只用销量的季节性统计基线**，再在数据条件满足时加入价格、油价、宏观等外部变量；无外部变量的模型不能称为已经完成因素分析。统计相关性和模型系数不等于因果关系。

历史真实零售销量及其派生摘要不向外部模型或第三方发送。现有 DeepSeek 分析只允许按质量门发送未来预测信息。公司内部模型尚未核实服务地址、权限及数据边界，不作为本阶段默认依赖。

## 二、步骤一：建立季节性统计基线

### 现在有什么

1. 已有按月的真实零售销量读取能力，覆盖用户提供的省份及动力类型；当前工作簿版本记录为 2012 年至 2026 年的月度数据，最新具体截止以实际文件校验结果为准。
2. 您已确认：销量单位为辆、口径为零售；插电式混合动力含增程；已出现月份里缺失的省份／类别可按零处理，完整缺月不补零；四类合计不含燃料电池。
3. 已有 Chronos-2 预测、滚动回测和季节性基线的实现与记录，可借鉴数据读取、版本校验及回测定义。Chronos-2 是预训练模型的零样本推理，不是在这些销量数据上重新训练权重。
4. 当前已检查的模型目录中没有可直接使用的 SARIMAX 实现；项目主 Python 尚未发现 `statsmodels`。这只是本次检查结果，实施前仍需核对环境和依赖兼容性。

### 需要什么

- 确定第一批试点范围、历史截止月及对比窗口。您已确认先使用 **31 省四类小计和广东插混两个样本**：前者观察较大规模序列，后者观察您正在使用的地区细分；截止月及对比窗口按现有可靠数据核查。
- 只读取得经校验的连续月度销量与数据版本，明确缺月、零值和样本过短时的处理规则。
- 确定合适的统计建模依赖及兼容版本，先检查主 Python 的现有依赖，必要时提出隔离环境方案；未经验证不能在主环境盲目升级或覆盖包。
- 定义预测结果、统计区间、模型参数、训练截止、异常和回执的基本格式。

### 谁来支持

| 支持方 | 具体事项 |
| --- | --- |
| 您／业务负责人 | 确认试点地区、动力类型和业务口径；查看预测及结果是否符合使用场景。 |
| 当前值班 AI（Codex 或 TRAE） | 检查代码影响及依赖，复用月度序列，设计并实现独立统计模型、错误处理和测试；一次只由一方写入。 |
| 项目环境维护方（需要时） | 在依赖冲突或安装受限时协助确认可用环境；不直接改动业务数据。 |

### 建议什么

1. 先对选定范围做无外部变量的季节性统计建模：记录季节周期、候选参数、训练数据截止和收敛状态；候选范围应受样本长度和计算资源约束。
2. 每个回测起点只使用该起点之前可用的销量；模型参数选择也不能看到测试月份。缺月、数据不足、全零／恒定、非有限数或模型不收敛时明确报告，不默默编造结果。
3. 输出未来月度点预测和模型条件预测区间，并单独检查区间覆盖；SARIMAX 区间和 Chronos-2 分位区间的产生方式不同，不应假定校准效果相同。
4. **本步交付**：独立可运行的基线、输入与模型记录、预测回执、边界测试和一份初步回测。先让您看到结果，再决定是否扩大试点；不预先承诺优于 Chronos-2。

**进入下一步的条件**：基线能在约定样本上重现，时间切分及失败处理通过检查；若精度不佳，如实记录，不把“能运行”写成“业务精度已验收”。外部变量盘点可与您确认结果的过程并行做只读工作，但代码仍遵循单一写入方。

## 三、步骤二：整理外部变量与数据来源

### 现在有什么

1. 已有九月、十月的价格与权益监测表。九月可识别的当月日期为 2026 年 9 月 1 日至 21 日；十月日期汇总为 10 月 1 日至 26 日，均不能直接视为完整月份的成交价。两表有共同字段，九月另有“原文或截图位置”。
2. 同事整理的《新能源汽车涨降表(冰雨).xlsx》有按 2022—2026 年命名的涨降价工作表及新车权益、金融优惠等记录。部分日期没有明确年份，表格含合并单元格；工作表名称不证明每个月均有完整数据。
3. 项目已有价格权益监测台账、查询和展示链路；历史文档记录过真实接口与页面验收。**本次未连接服务器**，当前在线状态、历史覆盖和读取权限尚未确认。
4. 已查到的公开候选包括[国家统计局月度数据](https://www.stats.gov.cn/english/Statisticaldata/MonthlyData/)、[国内成品油调价公告](https://oilsyggs.mofcom.gov.cn/oil/gzdt/page1.html)和 [EIA 布伦特油价](https://www.eia.gov/dnav/pet/hist/rbrtew.htm)。候选不等于已采集、可自动获取或可直接建模。
5. Codex 中已有公开数据采集定时任务草案，建议每周一 09:00 检查，**目前暂停**；尚未进行首次采集验证，也尚未建设脱离 Codex 的独立采集程序。

### 需要什么

- 一份数据清单：来源、允许用途、覆盖时间、地区、品牌／车型／动力口径、单位、采集／发布日期、缺失、修订及是否可追溯。
- 核查历史价格权益文件和现有台账是否存在相同活动重复、车型更名、价格／优惠文本无法数值化、地区不明或活动开始／结束时间缺失。
- 业务认可的指标定义：例如是否以车型活动覆盖数、可核验的指导价变动或权益事件数表示，不得默认等于实际成交价；若使用均价或加权指数，必须明确样本和权重来源。
- 公开变量的实际来源、历史完整性、发布日期、修订版本及采集方式；国内成品油价格、国际原油价格和全国宏观指标含义不同，不能互相替代。
- 面向未来的外部变量：您已明确**基准情景由业务提供假设**。还需要按指标、地区和未来月份给出具体数值或可执行规则，并标明假设来源和版本。

### 谁来支持

| 支持方 | 具体事项 |
| --- | --- |
| 您／业务数据负责人 | 提供或指出可授权使用的历史文件，确认价格、权益和地区映射口径，以及未来基准假设。 |
| 当前值班 AI | 在本机只读盘点文件；自主检索公开来源，记录链接、发布日期、单位与缺口；提出清洗、事件去重和月度汇总方案。 |
| 现有价格权益系统维护方 | 必要时协助确认现有台账可读范围、采集与历史覆盖、字段解释及权限；不要求重建已有监测系统。 |
| 公司 IT／数据管理员（需要时） | 核验服务器访问权限、数据存储与出域边界。现有历史文档中的只读事务不等于已验证为独立只读数据库账号。 |

### 建议什么

1. **先盘点复用**：对现有台账和三个已提供文件做字段及时间覆盖清单，区分活动监测、指导价变更、权益描述和实际成交价；缺失年份或时间不自动猜测。
2. **小规模试做**：先选一个业务可解释的价格／权益指标，在本机整理样例，明确事件有效期、重复记录、地区与车型映射、统计规则和发布日期；由您确认后再扩展。
3. **补充公开数据**：优先核查统计局的 CPI、PPI 和社会消费品零售指标，以及国内成品油调价；国际布伦特原油作为候选对照，不能称作国内零售油价。先核验历史覆盖、修订、访问条件和实际用途，再决定采集范围。
4. **分两步自动化**：先验证一次公开数据采集、来源记录、去重和本机快照；您确认后再启用现有 Codex 定时任务。待采集流程稳定，再设计独立程序调度，不把现有 Codex 定时任务误认为独立服务。Codex 任务不自动写正式训练数据。
5. **本步交付**：数据源清单、覆盖与缺口表、各候选指标字典及可追溯样例、公开数据采集方案、待您填写的未来基准假设模板。不得因资料暂缺而伪造历史记录。

**进入下一步的条件**：至少一个变量具有可解释的定义和足够的可核验覆盖，且未来假设及数据可使用时间明确。若暂时不满足，保留步骤一基线和缺口记录，不宣称外部因素分析已完成。

## 四、步骤三：增加外部变量与滞后分析

### 现在有什么

- 当前销量序列和 Chronos-2 结果可提供预测对象及本地对比基础。
- 您已确定未来外部变量的基准情景由业务给出；具体变量和月度假设尚未提供。
- 九月、十月监测表与历史涨降价文件是候选材料；现有价格权益链路、公开宏观和油价来源仍待实测与口径审核。
- 目前没有经过验证、可直接运行的 SARIMAX 外部变量模型，也没有可直接复用的未来变量情景预测接口。

### 需要什么

- 步骤二验收过的变量样本：每条至少能确定对象、统计月份、数值与单位、来源、发布日期／可获得时间、修订版本和缺失状态。
- 每个历史回测起点对应的“当时能看到什么”：例如回测起点为 9 月末，10 月才公布的信息不能当作 9 月末已知事实。
- 由业务确定的未来基准假设；若需要比较情景，还需明确每个变量的调整方式、适用月份和依据。未提供未来值时，应提示缺少假设，不能拿未来实际值代替。
- 变量数量、滞后候选、数据量和稳定性诊断的约束，以及如何处理高度相关、缺失或样本太少的变量。

### 谁来支持

| 支持方 | 具体事项 |
| --- | --- |
| 您／业务负责人 | 选择优先分析的因素，提供未来基准假设，确认变量解释是否符合业务口径。 |
| 当前值班 AI | 建立时间对齐与滞后计算、选择合理的候选范围，记录估计和诊断过程，并验证防止未来信息泄漏。 |
| 数据提供方 | 在需要时解释发布日期、统计时点、修订及缺失，协助核查不确定的价格权益记录。 |

### 建议什么

1. 从少量、覆盖较完整且定义清晰的变量开始，而不是同时放入大量不完整指标；每次新增变量都记录用途、来源和可用时点。
2. 在每个滚动起点内部选择／估计滞后和模型参数，不能用未来回测段挑选最佳参数。历史修订版本缺失时明确标注限制，不能宣称完全复原历史时点。
3. 模型可以报告方向、估计系数、滞后、样本和诊断结果；表述为“模型中观察到的统计关系”，不可写成“某政策或价格变化导致销量变化”。
4. 情景比较必须按经确认的未来假设重新计算，并显示输入假设与版本；没有重算结果时不由大模型估算变化数字。
5. **本步交付**：变量对齐记录、基准假设表、带变量的独立预测结果、滞后与诊断报告、防泄漏测试，以及缺失数据和不收敛的处理记录。

**进入下一步的条件**：变量与未来假设可追溯，关键防泄漏和异常测试通过。若数据不足，应报告能完成到哪一步，不能把统计关联包装成因果结论。

## 五、步骤四：公平比较、网页接入与验收

### 现在有什么

- 新版页面已有 Chronos-2 预测、历史滚动回测、本机规则分析和 DeepSeek 固定意图分析；原市场预测功能保留。
- Chronos-2 现有回测记录包括 1、3、6、12 个月指标与季节性基线；另有用于参考门槛的独立 1—6 月窗口。两个窗口的起点可能不同，不能混成同一组比较。
- 第一阶段回测参考门槛未达，且比较口径不完全一致；业务精度及用户验收仍未完成。
- 当前预测分析接口及 DeepSeek 出域白名单绑定 Chronos-2 任务，**不是已经支持多模型的通用接口**。

### 需要什么

- 双方约定的试点对象、数据版本、预测起点、训练截止、对比周期和有效样本；对于不同方法，应保证可使用的信息及评分样本一致。
- 分别计算 1、3、6、12 个月的 MAE、WAPE、区间覆盖率和有效样本数；实际销量合计为零时 WAPE 明确记为不可计算。
- 新模型的独立接口和页面交互方案；涉及共享接口／跨模块架构时先协调确认。
- 适用于新模型的隐私质量门：外发只能是用户允许的预测字段，不能因为新增模型而把历史销量、回测记录或自由问题发给 DeepSeek。
- 页面验收要求、精度门槛及是否用于正式业务的判断标准；在您确认前，不以某个模型自动胜出或对外可用作为结论。

### 谁来支持

| 支持方 | 具体事项 |
| --- | --- |
| 您／业务负责人 | 选择需要查看的比较范围与页面呈现，确认业务验收门槛及是否允许用于正式业务。 |
| 当前值班 AI | 做同口径回测、独立 API／页面对接、隐私负向测试、旧功能回归和使用说明；交班时更新任务记录。 |
| TRAE 或 Codex 接班方 | 按 V2.0 读取同一任务和交接继续；不是必须相互逐项审查，也不与当前执行者同时写入。 |
| 公司 IT／数据管理员（需要时） | 协助核验外部模型调用的目标地址、部署环境和数据流向。 |

### 建议什么

1. 对相同预测对象、数据快照、起点和预测期，分别对比 Chronos-2、SARIMAX 与季节性基线；保留每个起点结果、模型参数和失败记录，避免只展示某一次最好的结果。
2. 页面优先增加**独立模型选择和对比视图**，展示数据范围、截止日、预测情景、区间、回测指标和数据限制；具体布局先与您确认，原预测入口保持可用。
3. 回测是对当前历史快照的评估；若缺少过去发布版本，须显示这一限制。不同模型的区间解释和实际覆盖应分别展示，不能只比较区间宽度。
4. DeepSeek 若要解释 SARIMAX，先单独设计模型适配与严格字段白名单；只有验证通过的未来预测信息可发送，历史、回测、自由提问与对话不能随之出域。当前不默认它已经支持 SARIMAX。
5. **本步交付**：可复现的比较表与逐起点回执、新模型页面和使用说明、隐私测试、必要旧功能回归和业务验收清单。精度不达标时如实呈现，保留继续改进路径。

**完成条件**：功能与安全测试通过、比较口径可复核、已知问题记录完整，并由您完成相应业务验收；未达标不能标为全面验收通过。
