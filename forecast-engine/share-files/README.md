# HelloAgent 双 AI 轮班接力 · V2.0

此目录原为市场预测试点，现复用为整个 myproject 的共享状态入口。共同规则以 [项目 AGENTS.md](../../AGENTS.md) 为准，目录位置不代表固定模块分工。

- [TASKS.md](TASKS.md)：项目研发任务索引与当前值班状态；由当前执行者维护。
- [HANDOFF.md](HANDOFF.md)：最近一次交班/继续开发摘要；由当前执行者维护。
- tasks/<任务编号>/TASK.md：对应任务的要求、步骤、进度和验证。原任务文件保留，当前执行者可根据实际进度维护。
- tasks/ 中既有 TRAE_REPORT.md、CODEX_REPLY.md：历史记录，按需查阅，不再是强制交接或互审流程。
- 若以后存在 API_CONTRACT.md，继续按技术契约维护；本次规则切换不创建或改写业务接口设计。

开工按需查看 AGENTS.md、TASKS.md、HANDOFF.md、当前任务 TASK.md 和相关代码；先核对 Git、已暂存/未暂存及未跟踪成果。项目任务执行前在当前 TASK.md 拆分步骤，完成一步更新状态、验证和下一步。只读咨询和本次规则文档调整不为形式而新建任务编号；新任务编号或目录须先获用户明确确认。

同一时间仅一个 AI 负责项目代码和共享状态写入。交班时当前执行者保存任务状态，在 HANDOFF.md 记下任务及进度、修改文件与 Git 提交/未提交情况、测试结果、未解决问题和下一步，然后停止写入；接班方从现有代码继续。突然中断时 HANDOFF 可能尚未更新，以已保存的 TASK.md 和实际 Git 状态核实。

每位执行者自行完成必要测试；关键里程碑、跨模块集成和正式发布前组织统一验收。用户没有明确要求时，不强制逐项跨 AI 审查、重新分派或反复讨论。原市场预测保持不变，Chronos-2 作为独立新增能力；重大架构重构、数据库破坏性变更和删除功能先经用户确认。

不向任务记录写密钥或会话凭据；不以未跟踪、未暂存或已暂存作为删除依据。未经授权不提交、推送或部署。历史任务及报告保留原位置，不因切换规则迁移或删除。
