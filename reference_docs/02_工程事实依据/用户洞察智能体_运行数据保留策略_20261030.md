# 用户洞察智能体 · 运行数据保留策略（`retrieval_run`）

版本日期：2026-10-30
适用范围：`user_insight.retrieval_run` 及用户洞察查询运行过程中产生的 PII 相关运行记录。
定位：本文件是 `retrieval_run` PII 保留与清理策略的唯一真源；T1 只更新规范与 Schema 设计文档，不执行生产数据库变更；T2 实施 Schema 时同步实现保留期限、自动清理及相关测试。

## 一、保留期限

1. 原始查询正文 `question`：**默认不持久化**。
2. `query_hash`（HMAC-SHA256）：保留 **30 天**。
3. `query_summary`（脱敏摘要）：保留 **30 天**；无法可靠脱敏时不保存。
4. `run_id`、执行状态、耗时、工具调用次数、错误码等非敏感运行元数据：保留 **90 天**。
5. 正式研究报告、访谈证据库及标签数据不按此策略删除，遵循独立的业务数据管理制度。

## 二、具体技术要求

1. 现有 Schema 中 `retrieval_run.question TEXT NOT NULL` 调整为可选的 `query_hash`、`query_summary`，不要默认存完整问题。
2. 哈希采用 **HMAC-SHA256**，通过受保护的服务端密钥生成，不使用无密钥的普通 SHA256 直接处理原始提问。
3. 脱敏摘要应去除姓名、电话、身份证号、详细地址等可识别信息；不保存不必要的访谈原话。
4. 每日执行自动清理：超过 30 天后清空查询哈希、脱敏摘要及不再需要的敏感关联字段；超过 90 天删除非必要的运行记录。
5. 清理过程记录数量、执行时间、成功或失败状态，**不记录被清理的敏感内容**。
6. 原始问答、异常日志、Trace 及备份都应检查是否存在其他副本，避免只清理主表却继续长期保留敏感信息。
7. 对需要调查的异常事件，如存在合法的延长保留依据，应走授权审批，并明确保留范围、期限及访问权限。

## 三、与安全日志分开

`retrieval_run` 属于用户洞察业务运行记录，**不等同于网络安全审计日志**。网络安全日志依据公司适用的合规制度和法律要求另行保留，不得以本次 30 天或 90 天策略替代。

## 四、实施阶段

- **T1**：只更新工程规范和 Schema 设计文档，不执行生产数据库变更。
- **T2**：实施数据库 Schema 时同步实现保留期限、自动清理及相关测试。
