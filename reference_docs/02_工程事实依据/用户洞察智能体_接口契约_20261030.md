# 用户访谈证据问答接口契约（第一阶段）

## 设计原则

- 不改变现有页面布局；只在既有结果区域内追加“证据”区块。
- 不改变 `/api/chat` 的市场战略与预测语义；用户洞察走独立接口分支。
- 证据由后端检索结果直接生成，不能由模型自由编造。
- 模型正文中的引用编号必须能在后端 `evidence[]` 中找到。

## 1. 同步问答

`POST /api/insight/interview/query`

请求：

```json
{
  "question": "为什么沈阳的小米YU7用户最终没有选择Model Y？",
  "filters": {
    "city": ["沈阳"],
    "vehicle_model": ["小米YU7"],
    "purchase_type": ["换购"],
    "question_ids": [4, 8, 22],
    "tag_names": ["购车原因", "竞品对比"]
  },
  "top_k": 8,
  "session_id": ""
}
```

约束：

- `question`：1–2,000 字符。
- `top_k`：1–12，默认 8。
- `filters` 只接受白名单字段；不接受任意 SQL、任意字段名或任意表达式。
- `session_id` 第一阶段可忽略；留出多轮扩展位。

成功响应：

```json
{
  "run_id": "ins-20261030-153000-a1b2c3d4",
  "status": "completed",
  "agent": "user_insight_config",
  "answer": "沈阳小米YU7的换购用户更强调…… [E1][E3]",
  "evidence": [
    {
      "evidence_id": "E1",
      "respondent_code": "R045",
      "city": "沈阳",
      "vehicle_model": "小米YU7",
      "purchase_type": "换购",
      "question_id": 4,
      "question_text": "用户此次购车的主要原因是什么？",
      "quote": "我原来开的是宝马X3……",
      "speaker": "说话人1",
      "start_sec": 612.6,
      "end_sec": 621.5,
      "time_label": "10:12.6–10:21.5",
      "confidence": "非常自信",
      "source": {
        "source_format": "answer_json",
        "source_version": "20261008",
        "document_id": "R045-Q004",
        "checksum": "sha256:..."
      },
      "retrieval": {
        "rank": 1,
        "score": 0.913,
        "rerank_score": 4.58,
        "matched_by": "vector+rerank"
      }
    }
  ],
  "retrieval": {
    "query": "为什么沈阳的小米YU7用户最终没有选择Model Y？",
    "filters_applied": {
      "city": ["沈阳"],
      "vehicle_model": ["小米YU7"]
    },
    "candidate_count": 27,
    "returned_count": 8,
    "reranker_degraded": false,
    "latency_ms": 1840
  },
  "tool_events": [],
  "warnings": []
}
```

错误：

| HTTP | code | 条件 |
|---|---|---|
| 400 | `invalid_query` | 问题为空、top_k 越界、filters 非法 |
| 404 | `no_evidence` | 检索成功但没有匹配证据；仍返回 200 也可，推荐 200 + 空 evidence |
| 503 | `interview_index_unavailable` | 数据库/向量/检索服务不可用 |
| 504 | `retrieval_timeout` | 检索或 rerank 超时 |

> 推荐：无证据时返回 200，`status="completed"`，`evidence=[]`，正文明确“当前数据中没有可支持的访谈原话”，避免前端把“无数据”当故障。

## 2. SSE 流式接口（第二阶段）

`POST /api/insight/interview/stream`

响应头：

```text
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache
Connection: keep-alive
```

事件序列：

```text
event: run_started
data: {"run_id":"ins-...","status":"retrieving"}

event: retrieval_started
data: {"filters":{...}}

event: evidence
data: {"evidence":[...]}

event: answer_delta
data: {"text":"沈阳小米YU7的换购用户……"}

event: run_completed
data: {"run_id":"ins-...","status":"completed","evidence_ids":["E1","E3"]}
```

失败事件：

```text
event: run_failed
data: {"run_id":"ins-...","status":"failed","error":{"code":"...","message":"..."}}
```

实现建议：使用 AgentScope 2.0.3 已存在的 `Agent.reply_stream()`，但第一阶段先完成同步闭环；不要为了 SSE 重写整个 HTTP 服务。

## 3. 运行状态

`GET /api/insight/runs/{run_id}`

返回 `retrieval_run` 的公开字段：

```json
{
  "run_id": "ins-...",
  "status": "retrieving|answering|completed|failed",
  "created_at": "...",
  "completed_at": "...",
  "evidence_count": 8,
  "error": null
}
```

## 4. 引用校验规则

- 模型只能输出 `[E1]`、`[E2]` 这类证据编号。
- 后端扫描正文中的引用编号；不存在于本次 `evidence[]` 的编号视为无效。
- 有结论但无引用时，标记 `warnings`；不阻断正文展示，但必须提示“引用未完整覆盖”。
- `evidence[]` 由后端检索结果生成，不从模型输出反解析。
- 不返回姓名、电话等 PII；只返回 `respondent_code`、城市、车型、购车类型。
