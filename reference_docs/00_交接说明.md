# TRAE 用户洞察智能体 T0 完整交接包 V3.1

本包面向 TRAE IDE，只用于**读取参考与T0只读审计/规划**，不是执行安装程序。**不包含真实用户访谈音频、问卷明细或全部数据底座**。

## 阅读和执行顺序

1. 先读 `01_执行文件/01_TRAE_用户洞察智能体开发指南_V3.1.md`。
2. 执行 `01_执行文件/02_TRAE_第一项任务_T0_已有审计复核与CATARC借鉴.md`；T0严格只读，不修改代码和数据库。
3. 重点对照 `02_工程事实依据/` 下已有代码审计、API契约、SQL Schema。审计结论必须以**当前工作区实际代码**复核；SQL只读，不执行。
4. 根据 `03_数据底座说明/README_用户洞察智能体数据底座_v1.md` 理解已加工数据。若业务数据包可在授权内网访问，按需只读核实 `00_manifest/manifest.json`、`coverage_matrix.csv`、`data_quality_report.md`、`SHA256SUMS.txt`，并统计QA/证据/标签原始行数。若不可访问，记录“无法核实”，不可编造数据。
5. `04_优秀案例参考/` 只学习CATARC的项目隔离、SSOT、阶段契约、Hard Gate、Provenance、Checkpoint和Verify思想。它最初是给Codex的市场战略指导书，不可把其中针对市场战略的任务当作本次TRAE执行任务。
6. `01_执行文件/03_V3.1_CATARC案例融入说明.md` 仅解释版本变化，可选读。

## 开发分工

- TRAE：用户洞察智能体的业务模块、Workflow、Skill与独立API，按批准后的分阶段任务实施。
- Codex：市场战略智能体，现有预测业务保持不变。
- 共享文件`app.py`、前端公共文件、工具注册与公共Runtime/Harness需要先做最小影响分析；禁止覆盖其他工具的未提交更改。

## 冲突处理

当开发指导书、代码审计、API契约、DDL和当前源码存在冲突时，先列出差异，不擅自改写真源。以**当前源码、数据库真实状态和已确认的数据版本**为实现事实，以用户批准的API/Schema版本作为变更依据。

特别注意：数据底座README与代码审计文件对标签证据行数及证据片段口径有差异；核验原始manifest和实际数据后再定稿。

## 安全和禁止事项

- 原始访谈、身份信息、密钥、公司内部数据仅可在授权环境处理；未经授权不得发送给TRAE云端模型或外部服务。
- 本包只包含文档和Schema设计，不授权数据库写入、外网共享、安装其他框架或生产部署。
- 禁止把假数据、模拟进度或模型生成的原话当作真实业务验收。
- T0结束后输出审计差异、T1-T4最小计划、待确认风险并停止，等待用户批准。

## 旧版文档如何处理

之前的用户洞察规划方案、实施方案V1以及TRAE V2/V3指导书均是历史过程稿，不再向TRAE并行下达；V3.1为当前执行基线。
