# TRAE用户洞察实施指南 V3.1 修订说明

本次在V3的基础上，加入用户此前提供的同事优秀CATARC工程案例以及工程使用规范。**不是要求TRAE使用或迁移CATARC工程本身。**

## 新增内容

- CATARC真实文件参考入口：根`AGENTS.md`、专项`AGENTS.md`、`WORKFLOW.md`、`docs/HARNESS.md`、`tracking_v2_protocol.json`、`verify_harness.py`。
- 开发期Harness：单一真源、任务隔离、Git/worktree协作、测试门禁、收工更新状态。
- 运行期Harness：阶段契约、引用和个人信息Hard Gate、可回溯来源、工具降级与异常。
- Workflow：首期确定性检索链；不假装已有SSE/后台队列；不复制CATARC新闻采集业务。
- Verify：优先隔离数据库/脱敏测试数据，避免污染正式数据库；HTTP 200不能作为业务验收。
- T0任务新增“优秀案例借鉴矩阵”，用于明确学习范围、接入点和舍弃项。

## 保留V3事实结论

- 已审计网页后端为 `http.server.ThreadingHTTPServer`，**不是** FastAPI；已有 `/api/chat` 为同步JSON，**不是** SSE。
- AgentScope 2.0.3；`Agent+ReActConfig+Toolkit`；优先复用现有`SkillRunContext`和Job Manager。
- 三份新资料的SQL/API设计不重写，T0只读复核。
- `README`与审计报告中的标签证据计数和证据片段计数存在不同口径，必须以真实manifest和数据统计核对。
- T2-T4的验收是有真实证据回源的最小闭环；不影响市场战略和预测。
- 不把微调模型作为首期真实问答能力的前置依赖。

## 使用顺序

1. TRAE先读`01`开发指南。
2. TRAE执行`02`第一项T0只读任务。
3. 将T0复核报告交回审查；核定后才实施T1—T4。
4. 其他开发遵从现有项目`AGENTS.md`、Git协作和内部数据安全要求。
