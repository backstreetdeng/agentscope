## 0. 结论先行

**做法已定：单智能体 + 固定工作流。模型只做两件事——把问题归到 4 条模板之一，以及按模板给定的结构化中间结果写结论。取数、算术、阈值判断全部由代码完成。**

| 决策 | 结论 |
| --- | --- |
| 架构 | Router（意图识别）→ Workflow Runner（固定 DAG）→ Tool Layer（只读取数）→ Composer（模型合成）→ Validator（数字/引用/口径门） |
| 模板数 | 4 条：W1 单车型综合诊断、W2 双车对标、W3 单点深挖、W4 口碑专查；识别不出 → 反问一句，不硬猜 |
| 靶心 | 页面当前选中车型（下拉五款在库车型任一款），不写死 |
| 竞品 | **查出来的，不是问出来的**：`T8` 以本品为靶心跑战胜战败分组，按实际购买车型人数降序成池，默认取前 1–3；不读配置、不反问用户 |
| 双车对标的对接口径 | 复用既有战败口径做**双向对冲**（A→B、B→A 各自人数、比例、原因 TOP3），不新增指标、不设新门槛 |
| 四路分层 | 定量出比例（分子/分母/n）、深访出原话（人数，非比例）、流通出走势（未接入 → 空态）、口碑出本车评论分布（命中条数 + 分母）；四路平权，冲突并列不合并 |
| 首版范围 | P0 今天可演示：W1 + W2 + 10 个工具 + 数字校验 + 4 条用例 |
| 工时 | P0 约 1 个工作日（上午方案定稿、下午实施）；P1 再 2–3 人日 |

### 0.2 被否方案（不重复讨论）

| 方案 | 为什么不用 |
| --- | --- |
| 自由 ReAct 循环（模型自己决定调什么） | 同一问题两次跑出不同取数路径，结论不可复现；口径审计做不到。用户明确要求「固定骨架 + 模型只做判断」 |
| 多智能体编排（画像 Agent / 战败 Agent / 报告 Agent） | 四路数据串行依赖，拆角色后每个角色只调 1–2 个工具，收益接近零，延迟与失败点翻倍 |
| 纯上下文拼接（预先把所有指标塞进 prompt） | 指令一变就缺数据，模型会替缺失指标补数字 |
| 让模型自己算差值、占比 | 算术必须由代码完成，这是本项目唯一不能让步的一条 |

## 2. 事实基线（只读实测，不是推断）

### 2.1 靶心与竞品

- 靶心：`config/analysis_models.json` 下拉五款之一——零跑B10、铂智3X、iCAR 超级V23、海狮05、钛3。**靶心 = 页面当前选中车型**。
- 竞品：不是配置、不是业务清单、**也不是问用户**，而是每次查询由战胜战败题实时算出来的池（定义见 §2.2）。
- 用户问题里举例出现的车名（含原型示例车）一律不参与口径。

### 2.2 竞品池：竞品是查出来的，不是问出来的

业务说「竞品」「对标」时，智能体**不反问「跟哪台车比」**，自己走一遍战胜战败逻辑定位竞品：

1. **找对比过本品的人**：以当前目标车型为靶心，在定量 `Q3_22_1__1/2/3`（核心/次要/其他对比车型）中筛出「三列任一等于本品」的受访者。
2. **按实际购买车型分组、人数降序**：这些人的 `purchase_model` 分组结果就是竞品池——它和「XX 胜出」表的行是同一份数据（买了本品的人不算战败，不进池）。
3. **默认取池内人数最多的前 1–3 台**作为对比对象，直接进入 W2 双车对标。
4. **只有用户明确点名某台车时才改变默认**，且该车必须在池内；池外（含库内不存在）统一回「该车型与本品无对比样本」，并给出池内候选，不许编。

配套四条，必须同时成立：

- **实时计算**：池是每次查询现算，不落配置、不写死清单。`analysis_models.json` 只定义靶心下拉，不定义竞品。
- **池内人少的车照样能比**：不设人数门槛、不删除小样本行；结论里必须并列写出双方 n，小样本只出原话、不做优势判断（降级规则见 §5.2）。
- **池的来源是「实际购买」，不是「提到过」**：`Q3_22_1__1/2/3` 只用于判定「谁对比过本品」，池子的成员是这些人真正买了的车。
- **战胜侧不另建池**：战胜看 `Q3_23`（本品凭什么被选中）；战败看池内每一行的「谁赢走了我的人 + 原因」。双向对冲见 §2.4。

> 这一节决定智能体能否自己回答「我该打谁」。因此它排在所有模板之前：W1 的营销建议里的「对标对象」、W2 的「对比对象」、W3/W4 的补充维度，全部取自这一个池。

### 2.3 四路数据现状

| 路 | 落表 | 现状 | 可用形态 |
| --- | --- | --- | --- |
| 定量 | `user_insight.quant_sample` | 1,380 行 / 40 车型；五车 41 / 39 / 31 / 30 / 30 | 比例、均分、分布、排序（分子/分母/n 齐全） |
| 深访解析 | `user_insight.interview / answer / question / tag / tag_evidence` | 63 人 / 22 车型 / 85 题 / 5,355 作答；五车归并后 4 / 3 / 3 / 3 / 3 | **只能出原话**，任何按车型的深访比例都不成立 |
| 流通 | 无正式源 | 未接入；仅有 `new_car_monthly_sales_by_energy`（19,349 行，2025-01~2026-05，源「月度数据.xlsx」）与 `sales_import`（22,502 行，`source_caliber` 全空） | 本期空态 |
| 口碑（**第四路**） | `new_car_reputation_review_tag` 37,415 / `autohome_koubei` 34,649 / `dongchedi_koubei` 10,964 | 批次 `20261110T193628`，覆盖率 44.03%；五车分母 237–400 | 本车评论标签分布（命中条数 + 分母）+ 正负 TOP5 + 原话 |

> **口碑是第四路，不是旁证**（用户 2026-11-11 定稿）。它与定量、深访、流通平权参与综合结论，四个工作流里的口碑步骤都是固定步骤，不提供关闭开关。
>
> **但它的口径与问卷不同源**：口碑没有「同题同答」基础——问卷是同一批人回答同一道题，口碑是平台用户各自发帖、由打标归到标签。因此口碑只能描述**本车自身的评论分布**（某标签命中多少条 / 该车两平台去重评论总数），**不能做两车口碑差值，也不能写成「本品在某维度领先竞品 X%」**。这条约束在 v2.2 里升级为校验器硬门（§10.2 第 8 条）。

### 2.4 战败口径（竞品池与双车对标的全部依据，已定稿，不改）

`Q3_22_1__1/2/3` 任一列等于靶心，即「对比过靶心」；按 `purchase_model` 分组，每行给出「实际购车车型 + 人数 + 比例 + 原因 TOP3」；原因按靶心所在槽位取 `Q3_24_1/3/5`；**行内 ≥5 人且对比总数 ≥10 才给百分比**；不设样本量门槛、不并「其他」、不删行。实测样本：海狮05 整体 35 人 / 10 行。

**这张表就是竞品池**：每一行 = 一个池成员 + 人数。`≥5 人且总数 ≥10` 只决定该行**能不能给百分比**，不决定该行**在不在池里**——人少的行照样进池、照样可比，只是不给比例、只出原话。

双向对冲因此可以做成：

- A→B：靶心 A，看「买了 B」那一行（对比过 A 最后买了 B 的人、比例、原因）。
- B→A：靶心 B，看「买了 A」那一行。
- 两条都来自同一个既有口径，只是换靶心，**不新增任何指标定义**。

## 3. 架构：固定骨架 + 模型只做判断

```
POST /api/bci/analysis/agent/stream (NDJSON)
        │
        ├─ ① Router       意图 → {template, slots}  （模型，输出受 JSON schema 约束，单次调用）
        │                  识别不出 → 反问一句，结束（不进工作流）
        │
        ├─ ② Preflight    槽位补全（模型不给值，只做校验）
        │                  靶心 = 页面当前选中车型（前端必传，服务端不信模型）
        │                  竞品 = 本次 T8 池 TOP1，或用户点名且必须在池内（回显给用户）
        │
        ├─ ③ Runner       按模板跑固定 DAG，同层工具并行（asyncio.gather）
        │                  每步产出 StepResult{value, n, denominator, unit, question, table, as_of, caliber}
        │                  任一步 status != ok → 记录，不中断（缺口进 warnings）
        │
        ├─ ④ Derive       纯代码计算：百分点差、排序、归因分组、动作候选
        │                  模型不可见的中间层；所有派生数字在此生成并登记 numeric_index
        │
        ├─ ⑤ Composer     模型合成（单次调用，输入 = 结构化中间结果，不是原始行）
        │                  输出受「证据→归因→动作」骨架约束
        │
        └─ ⑥ Validator    数字白名单 / [E#] 引用 / 全称词 / 深访比例 / 口径冲突
                           失败 → 回退重写一次；二次失败返回错误码，不渲染
```

### 3.1 为什么不把「选工具」交给模型

四次调用（Router、Composer、可能的重写、追问）已经够。让模型在 11 个工具间自由 ReAct，会带来三个具体问题：路径不可复现（同一句话两次跑出不同数字组合）、题号容易猜错、超时。固定 DAG 把「该取什么」写死，模型只在两个受约束的位置出现，这是本项目「模型散文不是证据」规则的直接落地。

### 3.2 运行时不变量（需可测，不是口号）

| 不变量 | 判定方式 | 失败响应 |
| --- | --- | --- |
| 结论里每个数字都出自工具或 Derive 层 | 数字逐个查 `numeric_index` | 重写一次，二次失败整条不渲染 |
| 每个「动作」都能追到具体数据点 | 动作块必须带 `evidence_ref`（tool:metric 键或 `[E#]`） | 同上 |
| 靶心只来自前端，不来自模型 | Router 输出里不允许出现 `target_model` 字段 | 请求 400 |
| 竞品只能是本次 `T8` 算出的池成员 | Preflight 校验；池外车型一律「无对比样本」 | 400 + 池内候选 |
| 深访不出比例 | 含深访来源的句子不得出现 `%` 或「多数/大部分」 | 重写 |
| 口碑是固定第四路，不可关闭 | W1/W2/W4 的 DAG 必须含 `T5`；缺 `T5` 结果且无 `status` 说明视为执行失败 | 重跑该步；仍失败整条不渲染 |
| 口碑不得跨车相减或写成份额 | `T5` 返回里没有跨车字段；结论出现两车口碑差值或「领先竞品 X%」 | 重写（§10.2 第 8 条） |
| 同一指标两源不一致必须并列 | 校验器检查是否存在 `conflict_pair` 未并列 | 重写 |

### 3.3 责任与回退

- 运行责任：本模块由竞品洞察后端承担；Agent 异常降级为「只出四磁贴确定性结论 + 一句原因」，不返回半成品假结论。
- 回退成本：Router 与 Composer 是两个独立提示词文件，模板 DAG 用配置描述。换模型或改模板不需要动工具层；工具层改动不需要动提示词。这是一次可逆决策（two-way door）。
- 触发重估的条件：若 P1 出现「模板外问题占比 >30%」，再考虑开放第五模板或允许模型选工具；当前不做。

## 4. 意图路由

### 4.1 路由表

| 模板 | 触发特征 | 必填槽位 | 缺槽位处理 |
| --- | --- | --- | --- |
| W1 单车型综合诊断 | 一句话里要 ≥2 类指标（关注 / 战胜战败 / 满意度 / 画像），或出现「综合」「整体」「怎么打」「如何营销」 | `target` | `target` 前端必传，缺则 400 |
| W2 双车对标 | 出现「对比」「差异」「vs」「和…比」，且要的是画像 / 关注 / 战胜战败 | `target`、`competitor?` | `competitor` 缺省 → 池内人数 TOP1（最多取 3 台），回显「本次对标：<A> vs <B>（池内第 k）」；**不反问** |
| W3 单点深挖 | 只问一类指标（「最在意什么」只看关注；「为什么没买」只看战胜战败；「满意度短板」只看满意度） | `target`、`metric` | `metric` 不明 → 反问「你想看：购车关注 / 战胜战败 / 满意度 / 画像，哪一类？」 |
| W4 口碑专查 | 出现「口碑」「评论」「负面」「吐槽」 | `target` | 无 |
| unknown | 超范围（写 PPT、改数据、预测销量、推荐买哪款） | — | 拒答 + 一句引导，不进工作流 |

路由只输出 `{template, slots, confidence}`，**不允许输出任何车型名以外的业务数值**。`confidence < 0.6` 或 `template=unknown` 且不属于可拒答类型时，反问一句。

### 4.2 竞品解析（查出来的，不是问出来的）

`T8 bci_competitor_candidates(target, top_k=3)`：

1. 按 §2.4 口径跑一次「以 target 为靶心」的分组——**直接复用 `_loss_split`，与「XX 胜出」表同源**，不另写 SQL；
2. 每行就是一个池成员：`{model, people, total_compared, ratio|ratio_hidden_reason, reasons[3], quant_n}`，按 `people` 降序；
3. **不设人数门槛、不过滤小样本**；`ratio` 是否给值只看「行内 ≥5 人且总数 ≥10」；
4. 默认取前 1–3 台进入 W2，回显「本次对标：`<A>` vs `<B>`（池内人数第 n）」。

判定规则：

| 情况 | 处理 |
| --- | --- |
| 用户说「竞品/对标」但没点名 | 不问，直接用池内 TOP1–3 |
| 用户点名 `<B>` 且在池内 | 按 `<B>` 跑 W2，其余维度照常 |
| 用户点名 `<B>` 但不在池内（无论库内是否存在） | 回「该车型与本品无对比样本」，附池内候选，**不进 W2、不出数字** |
| 池为空（本题无人对比过本品） | 回「本品暂无对比样本，无法定位竞品」，并提示改用单车型诊断 |

模型只能从返回列表里选，不能生成车名；服务端在 Preflight 做存在性校验，不依赖模型自觉。

## 5. 工作流图

### 5.1 W1 单车型综合诊断（今天做）

用途：用户示例问题一「综合对比用户购车关注、战胜战败原因以及满意度评价，<目标车型> 应该如何对标竞品开展营销」。

```
S1  T1 context(target)                          ← 各源样本量、缺失源
    │
S2  ├─ T2 quant(target, attention)    ┐
    ├─ T2 quant(target, profile)      │ 并行（asyncio.gather）
    ├─ T3 winloss(target)             │
    ├─ T4 satisfaction(target)        │
    └─ T5 reputation(target, pos/neg) ┘
    │
S3  T8 competitor_candidates(target)            ← 竞品不是模型想的，是数据算的
    │
S4  T6 interview_quotes(target, topic=战败原因 / 关注点)  ← 只取原话，限 6 条
    │
S5  Derive（纯代码）：
     · 关注 16 维按勾选率降序，标出「入场券 / 竞争重点 / 加分项」分档
     · 战胜侧原因 TOP3、战败侧「谁赢走了 + 原因 TOP3」
     · 满意度低分维度 TOP3（与关注度交叉 → 机会点）
     · 每个机会点绑定一条可引用证据（指标键 or [E#]）
    │
S6  T7 circulation(target)  → 未接入则空态，warnings 记录
    │
S7  Composer：证据 → 归因 → 动作（三段，见 §8.2）
    │
S8  Validator
```

中间产物形状（示例，数字为占位）：

```json
{
  "step": "S5",
  "opportunity": {
    "metric": "attention.Q3_13__<k>",
    "label": "<维度名>",
    "count": "<N1>", "n": "<N2>", "ratio": "<P1>",
    "compare_gap_vs_competitor": "<P2>",
    "evidence": ["T3:loss.<B>.reason[0]", "T6:E<k>"],
    "confidence": "中"
  }
}
```

> S2 里的 `T5 reputation` 是**第四路的固定步骤**，不可摘除、不设开关；它的产出在 §8.2 的【一、证据】里必须出现（本车正/负 TOP 标签 + 命中条数 + 分母），且只描述本车。

### 5.2 W2 双车对标（今天做）

用途：用户示例问题二「对比本品和竞品，用户画像、购车关注有何差异」。**「竞品」由 §2.2 的池子决定，不问用户。**

```
S1  T8 competitor_candidates(A)                    ← 实时算池，不读配置
    · 用户未点名 → 默认 B = 池 TOP1（可选 TOP2/TOP3 追加对比）
    · 用户点名   → 校验 B ∈ 池；不在池 → 「该车型与本品无对比样本」，终止
    · 回显：「本次对标 <A> vs <B>（池内第 <k>，<M> 人；占本品对比总数 <P>%）」
    │
S2  并行取数（同层 asyncio.gather，单步失败不中断）
    ├─ T1  context(A)              ├─ T1  context(B)
    ├─ T10 compare_metric(A,B,profile)       ← 用户画像
    ├─ T10 compare_metric(A,B,attention)     ← 购车关注
    ├─ T9  head_to_head(A,B)                 ← 战胜战败归因（双向）
    ├─ T4  satisfaction(A)         ├─ T4  satisfaction(B)
    ├─ T5  reputation(A,pos/neg)   ├─ T5  reputation(B,pos/neg)   ← 第四路：各自自车分布，不做跨车差值
    └─ T6  interview_quotes(A)     └─ T6  interview_quotes(B)
    │
S3  T7 circulation([A,B])  → 未接入，空态（走势对比今天不做，见 §0.1）
    │
S4  Derive（纯代码）：
     · 五类维度逐项算：两侧 count / n / ratio + delta_pp（百分点）
     · |delta_pp| >= 5 记 significant；任一侧 ratio=null 记 insufficient，不给差值
     · 双向对冲并列：A→B 与 B→A 的人数、比例、原因 TOP3
     · 每类维度标降级级别（见下表）
    │
S5  Composer：差异 → 归因 → 各自短板
S6  Validator（额外：不得合并两车型分母；口碑不得写成跨车份额）
```

**对比维度（限定这五类，不多不少）**：

| 维度 | 工具 | 两侧必须同时给 | 单侧不足时 |
| --- | --- | --- | --- |
| 用户画像 | `T10` profile | `count/n/ratio` × 2 | 转为定性描述 + 原话，不给比例 |
| 购车关注 | `T10` attention（16 维） | 同上 + `delta_pp` | 同上 |
| 战胜战败归因 | `T9`（+`T3`） | `people/total_compared/ratio` × 2 + 原因 TOP3 | 只给人数与原因原话 |
| 满意度 | `T4`（16 维可比部分） | `mean/answered` × 2，仅比两侧都有作答的维度 | 该维度标「样本不足」，不出差值 |
| 口碑 L3 点（第四路） | `T5` | 各自 `count/denominator`，**分行并列，不计算差值** | 单侧 <3 条不进榜 |

**样本不足的降级规则（写进工具、提示词与校验器）**：

| 级别 | 条件 | 输出形态 | 禁止 |
| --- | --- | --- | --- |
| L0 完整 | 两侧 n ≥10 且该行 ≥5 人 | 比例 + 百分点差 + 双 n | — |
| L1 单侧偏薄 | 一侧 n <10 或该行 <5 人但 >0 | 只给人数与原因原话；差值 `null` | 给百分比、说「高于/低于」 |
| L2 单侧为空 | 一侧本题 0 人 | 「该维度 `<B>` 无作答样本」 | 用另一侧数据代替、估算 |
| L3 无源 | 维度本身无数据（如流通） | 「未接入/无数据源」 | 用邻近指标顶替 |

> 口径说明：五款在库车型定量 30–41 人，通常落 L0；但池内小样本车型（如只有 1–2 人对比过本品）会落 L1，**照比、标 n、不判优劣**——这是用户明确要求的行为，不是缺陷。

**双车对标的硬边界**：

1. 不给「A 比 B 好」的总评分或综合指数——库内没有可支撑的加权口径。
2. 不给「重叠人群」估算——两份问卷独立抽样，不能求交。
3. 差值只能说「本批样本中 A 比 B 高 <D> 个百分点」，不能说市场层面领先。
4. 战败双向数据只解释「谁赢走了谁的人」，不外推市场份额。
5. **口碑是第四路，但只出本车分布**：只能分行陈述「`<A>` 的负面集中在 `<标签>`（<N>/<N2>）」「`<B>` 的负面集中在 `<标签>`（<N>/<N2>）」，**绝不允许写成「本品在某维度领先竞品 X%」**，也不允许把两车口碑相减成「优势」。理由不是保守，而是口径不成立：口碑**没有同题同答基础**——问卷是同一批人回答同一道题（同题、同答、同分母），口碑是各平台用户各自发帖、再由打标归到标签，两侧题目、作答方式、分母来源都不同源，相减得到的差值没有统计含义。

### 5.3 W3 单点深挖（P1）

```
S1 metric 判定（attention|winloss|satisfaction|profile）
S2 单个工具（+ 视需要 T6 原话）
S3 Derive 排序/交叉
S4 Composer：短结论（1 段）+ 一句可执行动作
S5 Validator
```
与 W1 的差别：不强制三段式，不产出营销方案，只回答被问的那一类。

### 5.4 W4 口碑专查（正式路由；排期在 P1）

```
S1 T5 reputation(target, positive) + T5 reputation(target, negative)
S2 T6 interview_quotes(target, topic=负面关键词)  ← 用户原话与平台评论分开呈现
S3 Composer：正负 TOP5 + 两类来源分行标注，不合并成满意度分数
S4 Validator：分母必须是该车型两平台去重评论数（五车 237–400），不得用 mention_count 当评论量；不得出现跨车差值
```

> W4 是四条正式工作流之一，不是可插拔的附加项；排期放在 P1 只是上线顺序，不代表可关闭。P0 阶段命中口碑类问题时，走 W1 里的口碑步骤（同样只出本车分布），不返回反问、不排除口碑。

## 7. 四路数据在同一张结论里怎么分层

一段结论只能有一个「主张」，但证据可以来自多路。**四路平权**：没有哪一路是「旁证」，也没有哪一路可以被关掉；平权不等于可以互相替代，每一路的表述形态受各自口径限制。

| 层 | 允许出现在 | 表述形态 | 禁止 |
| --- | --- | --- | --- |
| 定量 | 任何主张的理由与幅度 | 「<维度> 勾选率 <P1>%（<N1>/<N2>，n=<N3>）」 | 代表全市场、推断因果 |
| 深访 | 解释动机、补充语境 | 「受访者提到「<原话>」[E<k>]（深访 <N> 人，非比例）」 | 任何百分比、「多数/大部分」 |
| 流通 | 规模与走势（本期无） | 「流通数据尚未接入，本次结论不含规模维度」 | 用销量表顶替、估算、说成上险量 |
| 口碑（**第四路**） | 与定量、深访、流通平级参与任何主张 | 「平台评论中负面集中在 <标签>（<N> 条 / 分母 <N2>，汽车之家+懂车帝）」——**只描述本车，逐车分行** | 与问卷满意度合并成单一分数；**写成跨车份额（「领先竞品 X%」）；两车口碑相减** |

同一段里出现两路指向不一致时，写成并列句并标注各自测的是什么（例：「问卷中价格是首要关注，平台评论中续航抱怨最多——前者测购买决策权重，后者测用车后体验」），不选边。

### 8.2 W1 合成（证据 → 归因 → 动作）

```
输入：结构化中间结果（每项含 label / count / n / ratio / 题号 / 口径 / 可选原话）
输出结构（必须三段，逐段写）：
【一、证据】只陈述中间结果里存在的事实。每个数字必须原样引用，不得换算、不得四舍五入。
【二、归因】把证据归到 ≤3 条原因；每条原因必须挂 ≥1 个证据键。
【三、动作】≤3 条，每条动作必须指向【一】里的具体数据点（写指标键或 [E#]），并按"先补短板 / 再打差异 / 后守优势"排序。
禁止：劝购建议、市场预测、份额判断；不得出现"都/全部/唯一/仅有"；深访只能引原话并标人数；**口碑只能写本车分布（命中条数/分母），不得跨车相减、不得写成「领先竞品 X%」**。
篇幅：正文 ≤450 字。

示例（占位符）
【一、证据】<车型A> 购车关注前三为 <维度1> <P1>%（<N1>/<N2>，Q3_13__<k>）、<维度2> …；战胜侧首位原因是 <原因1>（<N3> 人，Q3_23__<k>）；战败侧 <车型B> 赢走 <N4> 人（<P2>%，该行 ≥5 人且总数 ≥10）；平台评论中负面集中在 <标签1>（<N5> 条 / 分母 <N6>，汽车之家+懂车帝）。
【二、归因】…（挂 T3:loss.<车型B>.reason[0]）
【三、动作】1) 针对 <维度1> 补 …（依据 T2:attention.Q3_13__<k>）；2) …
```

### 8.3 W2 合成（差异 → 归因 → 各自短板）

```
输入：pool_top（池内前 1–3 与人数）、dims[{key,label,a{...},b{...},delta_pp,gap_flag,level}]、
      双向对流、各自口碑 TOP5、各自原话
输出：
【对标对象】一句话说明为什么是它：「本次对标 <车型A> vs <车型B>；<车型B> 在池内排第 <k>，<M> 人在对比过 <车型A> 后选择它（<P>%，对比总数 <T>）」
【差异】只写 level=L0 且 |delta_pp|>=5 的维度，格式：「<维度>：<车型A> <P1>%（<N1>/<N2>）vs <车型B> <P3>%（<N3>/<N4>），差 <D> 个百分点」
【归因】≤3 条，只解释差异（挂证据键）
【各自短板】A 一条、B 一条，各挂证据
【样本说明】一句话列出本次落 L1/L2 的维度，写「仅原话，不构成比例证据」
禁止：合并后的单一百分比、重叠人群估算、综合评分、"领先/落后市场"；
      把口碑写成份额（如「<车型A> 在某维度领先 <车型B> X%」）；
      level≠L0 的维度给出"高/低"判断。
篇幅：正文 ≤400 字。

示例（占位符）
【对标对象】本次对标 <车型A> vs <车型B>；<车型B> 在池内排第 1，<M> 人对比过 <车型A> 后选择它（<P>%，对比总数 <T>）。
【差异】<维度1>：<车型A> <P1>%（<N1>/<N2>）vs <车型B> <P3>%（<N3>/<N4>），差 <D1> 个百分点；<维度2> …
【归因】…（T9:a_to_b.reason[0]）…（T10:attention.<key>）
【各自短板】<车型A>：…（T4:dim.<k>）；<车型B>：…（T5:negative.<tag>）
【样本说明】<维度3> 在 <车型B> 侧仅 <N5> 人，仅原话，不构成比例证据。
```

## 10. 数据契约与校验

### 10.1 统一返回信封

```json
{
  "tool": "bci_head_to_head",
  "args": {"a": "<车型A>", "b": "<车型B>"},
  "status": "ok | empty | not_available | error",
  "data": {},
  "caliber": {"n": 0, "denominator": 0, "unit": "人", "question": "Q3_22_1__1/2/3", "table": "user_insight.quant_sample", "as_of": "2026-11-11"},
  "hidden": ["ratio_hidden_reason"],
  "numeric_index": [{"value": 0, "meaning": "", "path": "data.a_to_b.people"}]
}
```

- `status=empty`：有源无数据（如某动力形式 0 人）；`not_available`：源未接入（T7）；两者必须分别渲染，不许统一成「无数据」。
- `numeric_index` 由工具自己产出（数值 → 含义 → 路径），Composer 的数字只能来自这里，加上 Derive 层登记项。

### 10.2 校验流水线

| # | 检查 | 失败处理 |
| --- | --- | --- |
| 1 | 数字白名单：结论中每个数字（含百分比、人数、辆数）在 `numeric_index` 中存在（允许 1 位小数） | 重写一次；二次失败返回 `E_NUM_UNVERIFIED` + 缺失项 |
| 2 | 引用：每个 `[E#]` 都必须来自本次工具返回 | 删除该句并重写 |
| 3 | 动作可追溯：每个动作块必须有 `evidence_ref` | 重写 |
| 4 | 深访不出比例：含深访来源的句子不出现 `%`、`多数`、`大部分` | 重写 |
| 5 | 全称词：「都/全部/唯一/仅有」+ 条目数 ≥2 | 重写 |
| 6 | 双车对标的合并检查：出现单一百分比且来源跨两车型 | 重写 |
| 7 | 口径冲突：`conflict_pair` 必须并列出现两个来源 | 重写 |
| 8 | 口碑写成份额：「领先竞品/优于竞品 X%」、两车口碑相减 | 重写 |
| 9 | 小样本做优势结论：`level ≠ L0` 的维度出现「高于/优于/领先」 | 重写 |

回退上限 1 次（沿用 `tile_summary` 的失败即报错、不用模板句兜底）。校验结果写 `verification` 字段与后端日志，**不在页面上给业务写「未校验/仅供参考」这类免责说明**。

### 10.3 样本门槛（沿用，不新增）

| 场景 | 规则 |
| --- | --- |
| 车型定量 <10 或本题作答 <10 | `ratio=null` + `ratio_hidden_reason`，只给人数 |
| 战败行 <5 人 或 对比总数 <10 | 只给人数，不给百分比 |
| 深访 <5 人（现状 3–4） | 永远只出原话，标「仅原话，不构成比例证据」 |
| 口碑单点 <3 条 或 分母 <50 | 不进榜 / 标「样本不足」 |
| `T8` 竞品池 | **不设人数门槛**：所有出现过的实际购买车型都进池并按人数排序；门槛只作用于「该行能否给百分比」（≥5 人且总数 ≥10） |
| `T10` 双侧比较 | 任一侧该题 n <10 或该行 <5 人 → `delta_pp=null`，只给人数与原话，不判优劣 |

## 13. 风险与不做

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 双车差异被读成市场结论 | 业务误用 | 固定句式「本批样本中…差 <D> 个百分点」；禁止综合评分 |
| 竞品被模型臆造 | 结论挂到不存在的车 | 竞品只能来自本次 `T8` 池；池外（含库内不存在）统一「无对比样本」，服务端 Preflight 校验 |
| 池内小样本被当成优势 | 1–2 人的车被说成「我们赢它」 | L1/L2 只给人数与原话，`delta_pp=null`；校验器拦「高于/优于/领先」 |
| 口碑被写成竞品份额 | 「本品在某维度领先竞品 X%」 | `T5` 不提供跨车相减字段；校验器第 8 条（硬门）；提示词明令禁止 |
| 战败双向样本过薄 | 单向数字夸大 | 沿用 ≥5 人且总数 ≥10；不满足只给人数 |
| 流通长期未接入 | 四路缺流通一路 | T7 空态；结论首句写明使用了哪几路；不因口碑升为第四路而放宽对流通的缺口标注 |
| 模板外问题堆积 | 用户反复被反问 | P1 统计 unknown 占比，>30% 再评估新增模板 |

不做：通用 SQL 工具；原始明细直出；写操作；多智能体编排；模型自行计算；页面写免责说明；用销量表冒充流通数据。
