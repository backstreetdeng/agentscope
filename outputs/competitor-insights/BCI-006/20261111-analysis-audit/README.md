## 2. 满意度评价：与原型的差异和代价（未自行改造）

> 2026-11-11 已拍板按原型改造，落地结果见 §2.1；本节保留当时的差异评估作为决策依据。

**现状（零跑B10，n=41）**：整体满意度均分 → 16 维打分 TOP5/BOTTOM5 + 全表 → 推荐意愿 1–10 分布 → 外部口碑正负向 TOP5（汽车之家 103 条）→ 本品进攻点一行 + 依据 + 现状核验。

**原型**：只给竞品逐卡片（4 张），每张 = 竞品名 + 满意度分（示例 8.3）+ 满意点 4 条 + 不满意点 3 条 + 本品进攻点 3 个方向；没有本品整体分、没有 16 维、没有推荐意愿。

**数据能不能撑起原型卡片**（库内实测）：

| 卡片要素 | 数据现状 | 结论 |
| --- | --- | --- |
| 竞品名 | 战败数据按「实际购买车型」逐行可取（零跑B10 战败池：铂智3X、深蓝S05 等） | 有 |
| 满意度分 | 定量 Q5_1 可按下单车型算，竞品购车人 n=30–65（深蓝S05 60、深蓝S07 62、零跑C11 60）；口碑平台均分为 5 分制（深蓝S05 4.59/122 条、零跑B10 4.60/103 条） | 有，但两种口径不可混用，需业务选一种 |
| 满意点 / 不满意点 | 竞品口碑逐车可取（每车 100–230 条，L3 单点需 ≥3 条才出） | 有，小样本竞品会大量空态 |
| 本品进攻点 | 现为跨 3 竞品取前 3；逐竞品需每车单跑 | 需改造成本 |

**改造代价**：后端逐竞品聚合 + 每竞品各跑一次进攻点（3× 模型、3× 联网核验、3 份缓存），约 0.5 天；前端卡片形态重写与空态约 0.5 天；测试约 0.25 天；合计约 1 天。**代价**：16 维打分与推荐意愿会从该卡消失（原型没有），竞品样本小、单点门槛会把多数竞品打成空态。

**建议（待你拍板）**：明天先定「满意度分用 10 分制问卷还是 5 分制口碑」和「16 维要不要保留」，再改；不确认口径直接改会出现两套分数并存。

## 2.1 落地结果：满意度主视图 = 逐竞品卡片（2026-11-11）

拍板口径与实现：

1. 竞品集合复用战胜战败 `_loss_split`（对比过本品、最终买了别的车），按战败人数取前 4 台。
2. 满意度分只用问卷 `Q5_1`（10 分制），每卡标 `n`；口碑平台五分制不进入卡片分数，也不与 10 分制并排。
3. 16 维满意度、推荐意愿、整体满意度与本品外部口碑收进卡片下方折叠区「本品自评：16 维与推荐意愿」，默认收起。
4. 每张卡的进攻点按该竞品单独算：该竞品负向口碑 L3 前 3 → 模型归成方向词 → 联网核验，走 `attack_point.build_attack` 缓存（键含提示词版本 + 数据哈希 + 联网结果哈希），第二次秒回。
5. 满意点 / 不满意点优先用该竞品口碑正负向 L3（每条带 `条数/分母`）；口碑样本不足则退回该竞品问卷 16 维高低分项，并在卡上标明「来源：该车问卷 16 维」。
