今天讨论的不是再增加一个聊天入口，而是把用户研究的方法变成能执行、能复核的咨询能力。业务提出问题后，AI需要知道该找什么资料、怎样比较不同解释、缺数据时怎么调整计划，最后把用户语言翻译成产品需求。这里所有目标能力和排期都属于规划建议，不能当作现有工程已经完成。首期用一个真实项目验证，再决定是否扩大投入。

01 / 业务价值

从材料自动化，走向可追溯的咨询决策

真正的提升不在于更快写字，而在于把研究结论连接到产品取舍。

当前常见做法

已有资料，却难以支撑决策

  • 访谈、问卷、口碑分散，复查原始依据耗时
  • 标签与数据描述较多，选择机制解释不足
  • “想要什么”难以转换为“应该怎么配”
目标能力

同一条证据链，支撑两类决策

  • 识别人群差异与购车取舍，说明支持证据和反例
  • 把场景痛点转成需求规格，而非直接堆配置
  • 在成本、依赖与工程限制下比较方案
价值衡量结论是否更可信、方案是否可比较、专家总投入是否下降。
规划建议 · 需经真实项目验证，不代表已交付能力02 / 22

原有工作里，资料本身往往并不少，难的是从材料到解释，再从解释到决策。自动整理和写报告仍然重要，但它们只是底层效率。这个项目要让业务能追问：这类人为什么流失，证据能否排除另一种解释，改产品还是改交易服务更有效。我们也不预设AI一定更好，最后要把专家修改时间算进去，和原来的方式比较，防止机器更快、人工返工更多。

02 / 职责划分

两个业务角色贯通研究与产品定义

先划清交接内容，再决定哪些底层功能封装为Skill。

A · 用户洞察与选择机制

  • 回答：服务谁，为什么买或不买
  • 研究：人群、场景、选择旅程、战胜战败
  • 输出：洞察、证据、反例、补访要求

B · 需求与配置权衡

  • 承接：已经审核的洞察与适用范围
  • 分析：需求规格、候选解法、成本与限制
  • 输出：配置方案、取舍、未覆盖需求
交接物：结构化洞察包

目标人群 + 使用场景 + 需求依据 + 置信与限制 + 待验证问题

市场战略Agent后续可提供目标市场边界；本期用户研究试点不以联动完成为前提。
规划建议 · 需经真实项目验证，不代表已交付能力03 / 22

这里的两个角色是职责边界，不是必须再做两个孤立聊天机器人。角色A解释用户差异和选择机制，角色B把审核后的洞察转成需求与配置比较。中间不能只传一段漂亮摘要，必须带人群、场景、原始证据和限制。战胜战败、需求识别和使用评价可以是共享Skill，不需要每项都单独设Agent。市场战略智能体将来能够提供范围，但不能让它成为当前试点落地的前置依赖。

03 / AI自主能力

自主能力必须体现在“选择下一步”

固定脚本负责确定性动作；AI负责受约束的规划、解释和调整。

任务规划

根据目标选择研究方法，形成步骤与停止条件

语义对齐

理解原声语境，对齐对象、否定和研究口径

需求发现

提出新需求或人群差异，并保留反例

选择机制

连接考虑、试驾、报价和最终取舍

主动补证

发现缺口或冲突，优先回查内部资料

需求翻译

从用户表述转换为可验证的产品要求

配置权衡

调用计算工具比较满足约束的备选组合

验证迭代

接受专家纠错，更新规则与回归用例

边界AI可以提出研究动作；外发数据、联系受访者、发布规则和正式交付需要审批。
规划建议 · 需经真实项目验证，不代表已交付能力04 / 22

这八项能力最关键的共同点，是会根据中间结果选择下一步。比如只有已购用户时，不该硬算战败率；两条原声互相矛盾时，不该挑一条支持自己。AI应能发现问题并调整任务。文件解析、比例计算、权限检查和成本求解还是交给程序。所谓自主，不意味着无限权限，也不意味着我们能看到模型全部内部思考，只需要记录计划、证据、工具结果和变更理由，让业务可复核。

04 / 执行机制

先检查结果，再决定继续、补证或暂停

业务可观察的是任务状态和调整依据，而不是一段模拟“思考日志”。

01明确目标

价格带、车型、时点、决策问题

02提出计划

数据源、方法、预算、审批点

03调用工具

筛样本、查原声、统计、求解

04检查结果

缺数？矛盾？越界？无解？

05交付或请示

达到门槛才交付；否则降级

发现缺口或矛盾 → 更新研究计划 → 重新执行必要步骤

可以自动处理

只读检索、证据校验、计算重跑、草稿修改。

需要人工批准

外部传输、追加调研、规则发布、正式报告签发。

必须停止或降级

权限不足、证据不够、预算耗尽、配置无可行解。

规划建议 · 需经真实项目验证，不代表已交付能力05 / 22

这条流程保留计划、工具执行、检查和调整四个关键状态。检查结果不是装饰节点：缺数据要返回补证，配置无解要保留冲突约束，权限不足要停止。每次重跑都留下原因、耗时、费用和版本，不让模型无限循环。业务看到的日志应是实际发生的状态和动作，而不是为了展示而预写的进度文案。最终报告由专家确认，尤其是涉及真实受访者联系或资料外发的步骤，需要单独审批。

05 / 首个咨询任务

为什么放弃车型A，转向车型B？

试点场景建议：15–20万元新能源SUV，最终范围由业务确认。

阶段AI采取的动作形成的业务产物
界定选择事件关联考虑车型、试驾、报价、成交或放弃时间可分析样本清单 + 有效分母

我们建议用从A转向B的选择问题做首个试点，因为它同时检验研究和配置两端。首先要有真实的考虑、试驾、报价和结果记录，不能把所有A车主都视为战胜样本。接着区分产品、交易和服务原因，再看证据能否支持。如果缺少流失用户，AI应该缩小结论范围并提出补样。最后只把已经审核的需求交给配置比较，而不是先定一个功能，再找几句原声为它背书。

06 / 洞察方法

每个洞察都要有支持、有反例、有适用边界

从“提及了什么”提升到“在什么场景下，为什么形成取舍”。

① 描述差异

  • 按研究设计识别人群与场景
  • 统一问卷口径、项目与时间范围
  • 不强制聚成三个固定圈层

② 解释选择

  • 关联考虑 → 试驾 → 报价 → 选择
  • 区分自述理由、相关关系与因果
  • 检查价格、产品、服务的替代解释

③ 反向检验

  • 谁没有这个痛点，为什么？
  • 是否存在支持相反解释的证据？
  • 不足处转成补访或验证计划
统计纪律访谈提及频次 ≠ 总体用户占比；口碑热度 ≠ 真实需求强度；偏好 ≠ 愿付价格。
规划建议 · 需经真实项目验证，不代表已交付能力07 / 22

用户洞察不能停在高频词和三个人群名称。差异、机制、反例要一起出现。定量数据解决比例和可比性，访谈帮助理解取舍过程，口碑用来发现线索，它们的统计意义不同。即使原声里很多人提到一个功能，也不等于整体市场愿意付费。选择机制还要区分产品与交易因素。我们希望最终每条结论都能说清适用于谁、依据是什么、哪些反例尚未解释，而不是用同一套标签套所有项目。

洞察审核后，下一步不是直接填配置清单。

比如冬天后排冷，不能直接判定用户需要热泵。需求是体验目标，配置是可能的解法。我们要把温度达到的时间、位置、场景等要求交给产品和工程确认，再比较不同技术方案。老人上下车不便也不一定靠空气悬架解决。这里的例子是方法示意，并不是已经得到的用户结论或工程指标。AI负责提出和对齐需求，技术可行性、性能阈值以及验证方式仍然需要专业人员审核。

08 / 配置决策

输出可比较的方案，不包装“最优配置”

真实成本和工程约束缺失时，只交需求优先级，不承诺自动优化。

01输入已审核需求

需求证据、目标用户、适用场景

02建立候选集合

真实成本、依赖、互斥、供应时间

03调用确定性工具

小规模枚举；复杂组合再用求解器

04比较取舍

需求覆盖、成本、剩余缺口与风险

基础保障包

优先满足刚性需求，在预算内减少未覆盖项。

体验增强包

对核心场景增加投入，明确牺牲了什么。

差异化探索包

保留创新假设，列出工程和用户验证条件。

求解结果要区分：可行、已证最优、无可行解、未完成证明；不能悄悄放宽硬约束。
规划建议 · 需经真实项目验证，不代表已交付能力09 / 22

配置权衡最容易出现虚假的精确感。没有真实成本，就不能算真实成本最优；没有经过验证的偏好权重，也不能承诺销量提升。首期适合先比较有限候选功能，明确需求覆盖和成本变化。若资料齐全，再由程序做枚举或约束求解。模型负责解释方案差异，不负责心算复杂组合。当条件冲突时，要返回哪个约束导致无解，请业务或工程决定，而不是为了输出答案偷偷删除限制。

所以，数据准备不能只有访谈和问卷。

这里最重要的是每种资料只回答它能回答的问题。问卷要有题目、跳题、量表和有效分母，访谈要有授权和上下文，配置要有真实成本和技术约束。页面上的数量只是工程试点建议，不代表统计抽样设计，也不是我们已经拥有的资产。历史资料还要检查年份与车型年款是否可比。专家案例最好配套原始数据和修改理由，这样才能学习判断规则，而不是只学习一句话的写法。

10 / 高质量数据集

音频入库只是起点，可信证据才是资产

建立原始层、处理层与审核层，不让清洗过程抹掉真实语境。

01授权与体检

用途、噪声、语言、保留与删除规则

02转写与角色

ASR、说话人、主持人区分、时间对齐

03脱敏与切分

原件隔离；片段保留前后文与匿名ID

04编码与审核

原句、对象、否定、标签、需求、证据

05评测与入库

双人标注、分歧仲裁、版本与追溯

金标准验证集

建议先准备300–500个片段，覆盖噪声、转述、否定和多说话人难例。

防止评测泄漏

按受访者或项目隔离训练示例与盲测集，不把同一人的相邻片段分到两边。

修正可以回溯

转写、标签和结论保留版本；授权撤回与删除能关联到衍生数据。

情绪和强度不得用“标签数量”代替；不能凭声音推断身份、人格或未经验证的心理特征。

高质量不是音频成功转成文字，而是每个结论能够回到正确的人和片段。群访里尤其要避免把主持人的引导问题当成用户观点。原始音频、清洗文本、标签和审核结果要分层保存，修正时能追踪影响。金标准需要双人独立标注和分歧处理，测试集要按人或项目隔离。情绪评价也不能靠标签数量，必要时先不做。首期可先从脱敏文本开始，避免同时承担完整音频平台的建设风险。
