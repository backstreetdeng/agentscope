# 用户智能体业务汇报HTML PPT

生成日期：2026年9月2日。两份材料采用 `html-ppt` Skill 的 `presenter-mode-reveal` 完整模板、`corporate-clean` 主题及流程、对比、架构、路线图版式重组。

## 两份演示文件

1. **20260902_用户洞察与需求配置匹配智能体_项目规划.html**：22页。用于完整项目汇报，叙事为“业务价值 → AI自主能力 → 研究与配置方法 → 数据与工程 → 验收与资源 → 请求决策”。
2. **20260902_用户智能体规划初版_逐页改进清单.html**：14页。用于和业务评审原方案；第3–13页逐一对应原PPT第1–11页，说明保留什么、补什么、如何修改。

两份HTML均为**独立单文件**，样式、图标、脚本和讲稿均内嵌。可以直接发送任意一份给同事，不需要同时发送其他目录。文件无需联网、无需启动Python或7860服务。外部参考链接只有主动点击时才需要网络。

## 如何汇报

- 用Chrome或Edge直接打开HTML。
- 左右方向键、空格或底部箭头翻页；`Home` 回首页，`End` 到末页。
- `F` 或底部全屏图标进入全屏。
- `O` 或九宫格图标打开页面总览，点击缩略图跳转；`Esc` 退出。
- `S` 或演讲图标打开演讲者窗口，可看当前页、下一页、讲稿和计时。首次使用需允许浏览器弹出窗口。
- `N` 或笔记图标在当前窗口查看讲稿；投屏时优先用独立演讲者窗口，避免观众看到讲稿。
- 手机支持左右滑动。画面保持16:9，建议横屏；正式汇报推荐电脑投屏。
- 浏览器打印采用横向16:9逐页样式；打印时关闭浏览器自带页眉页脚，需要保留底色时开启“背景图形”。

建议先讲22页规划稿，评审稿按业务追问定位原页使用，不必两套连续完整讲一遍。时间紧时，规划稿可优先使用第1、2、3、4、5、6、8、9、17、18、21页。

## 内容边界

- 来源为 `myproject/doc/plans/` 内两份同日期Markdown；原材料与原业务PPT未修改。
- 不是按每段文字机械拆页，而是按业务结论重组。每页有隐藏中文讲稿，保留数字、假设与能力边界。
- 目标能力、样本规模、排期、团队配置及验收阈值均为**规划建议 / 待验证目标**，不是现有系统已实现的成果。
- 现状描述是原规划时的检查记录，不代表实时系统状态；汇报前若系统有更新，应同步修改状态页。
- `source-map.json` 记录每页对应的来源章节、讲稿长度和生成文件哈希。
